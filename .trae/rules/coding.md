# Vibe-Coding 产品原型开发规范 (精简版)

## 一、 四大绝对铁律 (AI 行为准则)

1. 🔴 **Git 本地保护**：**严禁**执行破坏性命令（`checkout`, `switch`, `restore`, `reset --hard`, `clean -fd`）。**仅允许**创建新分支（`checkout -b`, `switch -c`）。
2. 🔴 **文档驱动 (先文后码)**：
   - **唯一入口**：任务第一步必须读取根目录 `README.md`。
   - **执行顺序**：`改文档` → `改代码`（纯格式化/改注释除外）。
   - **交付顺序**：先输出文档变更，再输出代码变更。
3. 🔴 **异常熔断 (遇错即停)**：
   - 遇错（非零退出码、error、超时）**立即停止，严禁盲试**。
   - **Sudo 规则**：读文件报错可自动尝试 `sudo`；写/删/改权/执行等高风险报错，**必须**暂停并询问用户。
   - **决策闭环**：报错 → 停止 → 给出方案 A/B → 等待用户确认。
4. 🔴 **拒绝废话**：**严禁**主动生成总结性文档（如 `Summary.md`, `ChangeLog.md` 等）。任务结束仅回复："任务完成，文档与代码已更新"。

## 二、 原型核心约束：离线可用 & 零构建

> **总原则**：产品原型的终态是一个**可直接通过浏览器打开的本地文件夹**，用户双击 `index.html` 即可运行，**不依赖任何网络、服务器、构建工具或命令行操作**。

1. **纯静态文件交付**：项目**仅允许**包含 `HTML`、`CSS`、`JS`、图片、字体等浏览器可直接解析的静态资源。**严禁**引入任何需要 `npm install`、`webpack`、`vite`、`tsc` 等构建/编译步骤的技术栈。
2. **零外部依赖（离线铁律）**：
   - **严禁**使用 CDN 链接引用任何外部资源（JS 库、CSS 框架、字体、图标）。
   - 若需第三方库（如轻量 UI 组件、图标库），**必须**将其 `.js` / `.css` 文件下载至项目 `libs/` 目录，通过**相对路径**引用。
   - 所有图片、字体等资源必须存放在项目 `assets/` 目录下，**严禁**使用任何外部 URL。
3. **轻量数据存储**：
   - 原型中的数据存储**仅允许**使用以下方式（按优先级排序）：JS 内存变量（推荐）、`localStorage`、JSON 文件 Mock。
   - **严禁**引入任何数据库或后端服务。
4. **无服务器依赖**：**严禁**编写任何依赖 HTTP 服务器才能运行的逻辑（如 `fetch('localhost:...')`、Server-Sent Events 等）。如需页面间数据通信，使用 `localStorage` 或 URL 参数传递。

## 三、 项目结构规范

```
项目根目录/
├── README.md              # 项目说明 & 页面索引（唯一入口文档）
├── docs/                  # 原型文档
│   ├── 页面清单.md         # 所有页面名称、文件路径、功能简述
│   ├── 交互说明.md         # 核心交互流程与状态流转
│   └── 数据结构.md         # Mock 数据结构定义（如需要）
├── index.html             # 原型入口页
├── pages/                 # 各页面 HTML 文件
├── css/                   # 样式文件
├── js/                    # 脚本文件
├── assets/                # 图片、字体等静态资源
│   ├── images/
│   └── fonts/
└── libs/                  # 第三方库本地副本（如有）
```

1. **结构 1:1 映射**：`docs/页面清单.md` 中登记的每个页面，必须与 `pages/` 下的文件保持 1:1 对应。
2. **README.md 作为索引**：`README.md` 必须包含：项目名称与简述、核心用户场景、页面索引（链接到 `docs/页面清单.md`）、打开方式说明（"双击 `index.html` 即可使用"）。

## 四、 标准工作流 (SOP)

处理任何任务，严格按以下 5 步循环执行：

1. **索引**：读取 `README.md`，定位目标页面与相关文档。
2. **修订**：更新 `docs/` 下对应文档（页面清单、交互说明、数据结构按需同步）。
3. **编码**：依据文档编写/修改 HTML、CSS、JS。编码时强制遵守：
   - 所有资源引用使用**相对路径**。
   - 编码完成后**人工在浏览器中以** **`file://`** **协议打开验证**，确认无控制台报错。
4. **验证与熔断**：以 `file://` 协议直接打开页面检查。若遇错 → 触发【铁律三】熔断机制。
5. **提交 (Commit)**：格式：`<type>(<scope>): <subject>`。
   - *Type 可选：`feat`,* *`fix`,* *`docs`,* *`style`,* *`refactor`,* *`chore`。*

***

### 💡 附：AI 快速自检清单（执行动作前默念）

- 我是不是要执行危险 Git 命令？ → 拒绝。
- 我改代码前改文档了吗？ → 没改先去改。
- 我是不是引入了需要构建/编译的技术栈？ → 换成纯 HTML/CSS/JS。
- 我是不是用了 CDN 或外部 URL？ → 改为本地 `libs/` 或 `assets/` 相对路径引用。
- 这个功能双击 `index.html` 能直接打开吗？ → 不能就重做。
- 刚才报错了，我要不要自己再试一次？ → 绝对不行，停下问用户。
- 任务做完了，我要不要写个长篇总结？ → 闭嘴，只说"完成"。
