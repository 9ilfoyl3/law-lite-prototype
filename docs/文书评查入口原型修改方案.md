## 二、交互设计

### 2.1 入口与形态：输入框底部工具条 + 引用按钮

```
┌─────────────────────────────────────┐
│  （消息区）                           │
├─────────────────────────────────────┤
│ ┌─────────────────────────────────┐ │
│ │ 描述要修改的内容...               │ │  ← textarea（占位不变）
│ └─────────────────────────────────┘ │
│ [☑ 文书评查]            [➤ 发送]     │  ← 新增底部工具条：左引用按钮，右发送
└─────────────────────────────────────┘
```

- 未激活态：`[文书评查]` 普通边框按钮，清晰文字标签（非纯图标，符合用户偏好：按钮要有明确文字标签）
- 点击后弹出**检查项勾选面板**（锚定在按钮上方，与系统弹窗风格一致：圆角、阴影、边框、遮罩分离）

### 2.2 检查项勾选面板（默认全选 10 项）

```
┌─ 选择评查角度 ──────────────── ✕ ─┐
│ ☑ 语言规范性   ☑ 法律用语规范      │
│ ☑ 事实要素一致性 ☑ 逻辑一致性      │
│ ☑ 法条引用完整性 ☑ 结构要素完整性  │
│ ☑ 诉请判项对应  ☑ 残留占位符检测   │
│ ☑ 语句精简     ☑ 场景错误风险提示  │
│ ──────────────────────────────────│
│ [全选]              [取消][开始评查]│
└───────────────────────────────────┘
```

- 检查项数据与《文书精修Agent编写方案》5.4 的 10 项完全一致（`CHECK_ITEMS` 常量：`id` / 名称 / 检查内容）
- 检查项清单（id → 名称）：
  - `typo` 语言规范性、`wording` 法律用语规范、`facts` 事实要素一致性、`logic` 逻辑一致性
  - `law_ref` 法条引用完整性、`structure` 结构要素完整性、`claim_match` 诉请判项对应
  - `placeholder` 残留占位符检测、`brevity` 语句精简、`scene_risk` 场景错误风险提示
- 一项不选时【开始评查】置灰（符合"不满足条件按钮置灰"惯例）
- 点【开始评查】→ 面板关闭，进入**评查模式**

### 2.3 评查模式激活态

```
┌─────────────────────────────────────┐
│ (i) 文书评查已启用 · 已选 10 项  ✕   │  ← 模式提示条（点 ✕ 退出）
├─────────────────────────────────────┤
│ ┌─────────────────────────────────┐ │
│ │ 评查无需输入指令，点击右侧开始    │ │  ← textarea 禁用置灰
│ └─────────────────────────────────┘ │
│ [文书评查 ✓]           [✓ 开始评查] │  ← 引用按钮高亮，发送变开始评查
└─────────────────────────────────────┘
```

- 引用按钮变为高亮选中态；再点它可重新打开面板调整勾选（面板内增加「退出评查」入口）
- textarea 禁用（与《文书精修Agent编写方案》5.4 保持一致：评查时 `instruction` 为空）
- 点【开始评查】发起评查，评查完成后自动**退出评查模式**，回到开放式问答（避免用户忘退）
- 评查进行中（流式输出期间）发送按钮沿用现有禁用逻辑

### 2.4 消息流渲染（复用现有 review 管线）

- **用户侧消息**：不渲染普通文本气泡，渲染「评查任务卡片」——标题"文书评查" + 已选检查项 chips，与普通问答在对话历史中明确区分
- **助手侧消息**：完全复用现有 `appendReviewMessagePlaceholder → streamAnalysisSteps → renderReviewList → streamReviewCards` 管线，仅两处小增量：
  1. 分析步骤标题按检查项动态生成（如"通读全文校对错字 → 核对事实要素一致性 → 检查法条引用 → 汇总评查建议"）
  2. 每张建议卡片标题旁显示**检查项标签**（蓝色小 tag，如"事实要素一致性"），对应《文书精修Agent编写方案》9.2 的 `checkItem` 字段
- 未发现问题时显示"未发现问题"空态（对应黄金测试集 T09：不凑数）

## 五、待确认决策点（2 项）

| # | 决策点 | 推荐方案 | 备选方案 |
|---|--------|---------|---------|
| 1 | 评查模式下输入框处理 | **禁用置灰**（与方案 5.4"评查无用户指令"一致，状态最清晰） | 允许输入补充关注点，随评查一并发送（更灵活但偏离方案） |
