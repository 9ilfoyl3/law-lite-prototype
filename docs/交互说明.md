## 一、全局交互规范

### 1.1 页面导航规则

| 动作 | 行为 | 说明 |
|------|------|------|
| 返回聊天 | `location.href = 'chat.html'` | 携带sessionID，保持会话上下文 |
| 切换模式 | 直接跳转对应页面 | 如从chat切换到cases.html |
| 新建任务 | 当前页面刷新重置 | 清空当前任务状态，回到初始态 |
| 浏览器后退 | 弹出确认提示 | 防止误操作丢失未保存数据 |

### 1.2 状态持久化策略

| 阶段 | 存储方式 | 说明 |
|------|----------|------|
| 原型阶段 | JS内存变量 | 最简单，页面刷新丢失 |
| 后续迭代 | sessionStorage / localStorage | 标签页级或跨标签页持久化 |

### 1.3 通用组件交互

#### 模态框（Modal）
- 点击遮罩层关闭
- ESC键关闭（可选配置）
- 确定/取消按钮居右排列
- 表单错误时实时显示提示信息

#### 确认弹窗（Confirm）
- 删除操作必须二次确认
- 批量操作显示具体数量（如"确定删除选中的5项？"）
- 危险操作按钮使用红色样式

#### 通知提示（Toast）
- 位置：页面右上角
- 类型：成功（绿色）、错误（红色）、警告（橙色）
- 自动消失：2.5秒
- 动画：滑入滑出

#### 加载状态
- 页面初始加载：骨架屏（Skeleton）
- AI处理中：进度条 + 步骤列表
- 文件上传：进度环 + 百分比
- 数据保存：按钮Loading旋转
- 页面切换：淡入淡出动画（300ms）

### 1.4 表单验证规则

| 规则 | 说明 |
|------|------|
| 必填校验 | 红色*标识，失焦时触发校验 |
| 格式校验 | 邮箱、手机号等正则验证 |
| 唯一性校验 | 用户名、分类ID等唯一字段实时校验 |
| 长度限制 | 显示剩余可输入字数 |

### 1.5 按钮状态

| 状态 | 样式 |
|------|------|
| 正常 | 标准背景色 |
| Hover | 略深背景色 |
| 禁用 | 灰色背景，不可点击 |
| 加载中 | 显示Loading图标 |

### 1.6 选择项交互

- **未选中**：空心方框 + 灰色边框
- **已选中**：实心勾选 + 蓝色边框 + 蓝色背景
- **禁用后**：降低透明度，不可点击

## 二、核心交互流程

### 2.1 用户登录流程

```
[登录页]
    │
    ▼
输入账号 + 密码 + 验证码
    │
    ▼
身份校验 ──成功──▶ 判断角色
    │失败              │
    ▼                 ├─ 普通用户 ──▶ [Chat欢迎页]
显示错误提示         │
    │                 └─ 管理员 ────▶ [Admin控制台]
    ▼
[登录页]
```

**交互细节**：
- 密码输入框支持眼睛图标切换显示/隐藏
- 验证码点击图片刷新
- 表单验证失败给出明确红色提示
- 登录成功后根据身份跳转对应页面

#### 2.2.4 历史任务页面（tasks.html）

> "历史任务"是独立页面，位于左侧导航栏"聊天"与"案件"图标之间。该页面**仅展示标准任务（裁判文书、庭审提纲、法条适用等）的历史记录**，与普通AI聊天会话分离，方便法官快速查找和回溯办案任务。
>
> 与 chat.html 历史会话侧边栏的区别：chat.html 的历史侧边栏展示**所有记录**（包含普通AI问答与标准任务），而本页面仅展示**标准任务**的历史。

    │
    ├─ 横向类型标签栏

    │       ├─ 法条适用
    │       └─ 知识问答
    │       └─ 选中标签蓝色高亮 + 底部下划线
    │
    ├─ 任务卡片列表
    │       └─ 每张卡片包含：
    │               ├─ 左侧图标
    │               ├─ 任务标题

    │               ├─ 创建时间
    │               └─ 悬停显示删除按钮
    │
    ├─ 任务卡片交互

    │       └─ 悬停显示删除按钮 ──▶ 点击 ──▶ 二次确认 ──▶ 删除
    │
    └─ 空状态
            └─ 无任务记录时显示："暂无任务记录"
```

### 2.3 V1.0 开放任务流程

> **说明**：Chat 页面任务选择器中，仅开放「裁判文书」「庭审提纲」「法条适用」三个办案任务入口。其余任务（类案检索、争议焦点、文本总结、文本润色、票据汇总）做隐藏处理，用户不可选择。
>
> 以下核心场景暂无独立任务页面，通过自然语言交互触发：文书质量评查、案由智能推荐、证据梳理、知识问答。

#### 2.3.1 裁判文书任务（对应核心场景：裁判文书生成）

**标准生成模式（五步法）**：

```
[发起任务]
    │
    ▼
Step 1: 材料上传与解析
    ├─ 上传起诉状/答辩状/证据清单（PDF/Word）
    ├─ 系统解析提取结构化信息
    └─ 显示解析进度
    │
    ▼
Step 2: 要件提取与确认 【检查点】
    ├─ AI自动提取法律要件（当事人信息、诉讼请求、事实理由等）
    ├─ 低置信度项高亮提醒
    └─ 法官逐项确认/修改/补充
    │
    ▼
Step 3: 法条推荐与选择 【检查点】
    ├─ 系统推荐适用法条（按效力层级排序）
    ├─ 标注法条状态（现行有效/已被废止）
    └─ 法官确认或手动替换法条
    │
    ▼
Step 4: 裁判方向笔记
    ├─ 法官输入裁判倾向、争议焦点处理意见
    └─ 支持引用前文已确认的要件
    │
    ▼
Step 5: 文书生成
    ├─ 流式输出判决书初稿
    ├─ 首字≤3秒，完整生成≤30秒
    └─ 附带"辅助生成，请核对"水印
    │
    ▼
[输出结果]
    ├─ 文档预览面板（右侧50%）
    ├─ 溯源功能：点击段落高亮显示来源
    └─ 操作：下载Word/PDF、收藏、转入编辑
```

**快速生成模式**：

```
[发起任务]
    │
    ▼
上传材料 ──▶ AI自动提取要件（无需确认）
    │           │
    │           └─ 法官可事后修改
    │
    ▼
一键生成初稿 ──▶ [输出结果]
```

#### 2.3.2 庭审提纲任务（对应核心场景：庭审提纲生成）

#### 2.3.3 法条适用任务（对应核心场景：法条检索与校验）

**主动检索模式**：

```
[发起任务]
    │
    ▼
输入：法条名称/编号/关键词/自然语言描述
    │
    ▼
筛选条件（可选）
    ├─ 效力层级：法律 > 行政法规 > 司法解释 > 部门规章 > 地方法规
    └─ 地域筛选
    │
    ▼
输出法条列表
    ├─ 法条全文
    ├─ 效力状态（现行有效 / 已被XX废止）
    └─ 相关案例引用次数
```

**自动校验模式（后台静默，服务于裁判文书任务）**：

```
裁判文书生成过程中 ──▶ 后台自动调用法条校验API
                                │
                                ├─ 法条正确 ──▶ 无感通过
                                └─ 法条有误 ──▶ 自动替换为数据库法条
                                                    │
                                                    └─ 标注"经系统校验调整"
```

### 2.4 自然语言触发的核心能力（暂无独立任务页面）

以下能力在 V1.0 不显示在任务选择器中，用户通过 Chat 输入自然语言触发：

#### 2.4.1 文书质量评查

```
用户输入："评查这份文书" / "检查文书质量"
    │
    ▼
系统识别意图 ──▶ 引导上传待评查文书
    │
    ▼
六维度评分
    ├─ 格式规范
    ├─ 事实认定
    ├─ 法条引用
    ├─ 裁判逻辑
    ├─ 语言表达
    └─ 程序事项
    │
    ▼
展示评查结果
    ├─ 雷达图总览
    ├─ 问题明细列表（定位到具体段落）
    │       ├─ 格式/法条类：支持"一键修复"
    │       └─ 事实/逻辑类：提示修改建议
    └─ 导出评查报告
```

#### 2.4.2 案由智能推荐

```
用户输入案情描述（自然语言）
    │
    ▼
系统推理案由 + 置信度计算
    │
    ├─ 高置信度(≥0.7) ──▶ 自动填入案由标签
    │                       └─ UI短暂提示"已识别为：XX纠纷"
    │
    ├─ 中置信度(0.4~0.7) ──▶ 输入框下方弹出候选案由列表(Top3)
    │                           └─ 等待法官点击确认
    │
    └─ 低置信度(<0.4) ──▶ 不显示结果，不打扰法官
```

#### 2.4.3 证据梳理

```
用户输入："梳理本案证据" / "分析证据材料"
    │
    ▼
Step 1: 材料输入
    ├─ 关联案件
    ├─ 上传证据材料（支持聊天记录截图）
    └─ 智能识别截图类型，提示"将启用深度解析引擎"
    │
    ▼
Step 2: 证据提取 【检查点 - 不可跳过】
    ├─ 通用模式：AI自动提取候选证据条目
    ├─ 聊天记录增强：
    │       ├─ 解析提取对话文本、时间戳、发送者身份
    │       ├─ 标记关键事实节点（"借款承诺""还款确认"等）
    │       └─ 证据强度预标注（红色标签标记"高风险事实"）
    └─ 法官逐条确认/修改/补充
    │
    ▼
Step 3: 分类编目
    ├─ 按证明目的/证据类型/当事人自动分组
    └─ 聊天记录支持按对话事件分组
    │
    ▼
Step 4: 关联映射 【检查点】
    ├─ 证据与要件/争议焦点关联矩阵
    ├─ 动态时间线（支持按参与人/时间范围/关键词筛选）
    └─ 证据链完整性诊断（断裂点虚线框标记）
    │
    ▼
Step 5: 效力初判 【检查点】

### 5.1 错误类型与处理

| 错误类型 | 处理方式 | 用户提示 |
|----------|----------|----------|

### 9.2 生成文书交互（行内触发 → 配置弹框）

**触发路径**：案件列表行 → 操作栏「生成文书」按钮 → 弹出配置弹框

**弹框内容**：
```
弹框标题：「生成文书」
弹框内容：
├─ 当前模型（下拉，可选轻量/标准/旗舰/长文本模型；标签右侧带提示图标，悬停提示「该配置功能为管理后台功能，用户不可见，方便演示展示」）
├─ 案件材料上下文预估（根据当前模型自动计算）
│   ├─ 未超限时："当前案件全部材料预估约 X tokens，未超过 Y 模型安全上限 Z tokens，将默认使用全部材料生成。"
│   └─ 超限时："当前案件全部材料预估约 X tokens，超过 Y 模型安全上限 Z tokens，请进入案件详情页选择核心材料生成文书；如勾选的核心材料仍超限，再使用分步生成。"
├─ 未超限时显示：文书类型、文书模板、提示词
└─ 底部主按钮
    ├─ 未超限时：【开始生成】
    └─ 超限时：【前往案件详情页配置】
```

**生成判断与跳转**：

1. 用户选择模型后，系统实时计算案件全部材料的预估 Token 总数 `getAllMaterialsTokens(caseId)` 与当前模型安全上限 `getSafeContextLimit(modelId)`
2. **未超限时**：
   - 弹框展示文书类型（必选）、文书模板（非必填，含「暂无可用模板」）、提示词（非必填）
   - 默认选中全部材料作为上下文
   - 若当前案由存在标准要件或我的要件，弹框内显示蓝色提示条"检测到该案由存在 X 个可用要件（标准 X / 我的 X），开始生成后将自动引入全部要件辅助生成"
   - 点击【开始生成】前校验文书类型是否为空；校验通过后弹框关闭，跳转 `pages/case-files.html?caseId=xxx&model=xxx&docType=xxx&template=xxx&requirement=xxx&source=list&autoGen=1&autoIntroduceElements=1`
   - 案件详情页自动应用传入的模型、文书类型、模板、提示词，默认全选材料并自动引入全部标准要件与我的要件（由系统预生成答案）后直接生成；生成完成后进入「生成完成态」，左栏材料树占 25%，右栏文书结果占 75%；用户可点击右栏【重新配置】回到配置态（中栏文书设置占 75%，右栏折叠）继续调整
3. **超限时**：
   - 弹框隐藏文书类型、文书模板、提示词，仅保留模型与上下文提示
   - 底部按钮变为【前往案件详情页配置】
   - 点击后弹框关闭，跳转 `pages/case-files.html?caseId=xxx`（效果同点击案件名称进入案件详情）
   - 用户在案件详情页选择核心材料并配置文书类型、模板、提示词后生成；若勾选的核心材料仍超限，再使用分步生成

**关闭规则**：点击弹框外部 / 关闭按钮 / 取消 → 弹框关闭，回到案件列表

  - 校验所有未生成步骤是否已选择材料；未选择时提示并展开对应步骤
  - 通过校验后，展开操作提示「请在各步骤中手动勾选与步骤主题相关的材料，系统将基于所选材料逐 step 生成」及步骤列表
  - 从第一步开始逐 step 生成；当前步骤生成中显示骨架屏，生成完成后显示结果与编辑/重新生成按钮
  - 在当前已生成步骤下方展示下一步操作按钮：未到最后一步时为【生成剩余步骤】，最后一步时为【生成文书】
  - 点击【生成剩余步骤】继续生成后续步骤；点击最后一步的【生成文书】完成全部步骤生成，并自动进入文书编译/展示
- 步骤列表按业务系统×文书类型自动确定（如法院裁判文书 6 步、检察院审查起诉 5 步、司法局行政复议 6 步）

- **材料表关系**：
  - 核心材料表：左栏材料树中被勾选的材料集合，用于一次性生成
  - 分步每步材料表：每个步骤独立维护的关联材料集合，是分步生成的上下文
  - 两张表相互独立：进入分步视图时，系统**不**预先把核心材料分配到各步骤，每步初始均为未选择状态
  - 每步材料由用户逐一手动勾选，通过材料选择器弹窗从全部案件材料中挑选
- 每步 body 内展示「关联材料」区域：
  - 采用「已选材料标签 + 材料选择器弹窗」的紧凑展示方式，避免在 100+ 材料场景下直接展开大量 checkbox
  - 每步展示写死的材料选择建议（如「案件信息」步骤提示「建议选择起诉状、立案登记表、案件基本信息表等」），引导用户按主题挑选
  - 未选择时显示「未选择材料」占位
  - 点击「选择材料」按钮打开材料选择器弹窗：
    - 顶部搜索框：按文件名实时过滤
    - 材料列表：以材料树形式展示全部案件材料，带滚动条的可勾选列表，支持全选/取消全选
    - 底部显示「已选 n / 共 m 件」与「确定」「取消」按钮
    - 实时 Token 校验：弹窗内实时统计已选材料预估 Token 数，若超过当前模型安全上下文上限，在底部显示红色提示「已选材料预估 x / y tokens，超出限制，请精简材料」，并将「确定」按钮置灰不可点击
  - 勾选/取消实时更新该步骤的关联材料集合
  - 点击「确定」关闭弹窗后，系统自动为该步骤生成 AI 识别内容
- 生成规则：
  - 每步生成仅基于该步已勾选材料
  - 若某步骤预估 Token 总数超过当前模型安全上限，提示「某某步骤预估 x tokens，超出当前模型安全上限 y tokens，请减少材料」
- 每步生成完成后展示：
  - 已选材料摘要：在生成结果上方显示「本步已选材料：xxx、yyy」，明确该步骤参考了哪些材料
  - 生成结果：以编号列表形式展示该步骤生成的内容条目
  - 操作按钮：编辑、重新生成
- 生成完成后：每步内容可编辑、重新生成；重新生成时仍只使用当前已勾选材料
- 全部步骤完成后：
  - 当前步骤下方按钮显示为【生成文书】
  - 点击后将所有步骤内容合并为完整文书并展示在右栏「生成结果」面板

#### 引入案由要件流程

> ⚠️ **适用范围（v1.27）**：要件（标准要件 + 我的要件）仅在文书类型为「裁判文书」（judgment）时才会询问是否引入。其他文书类型（庭审提纲、执行文书、材料总结等）生成时**不触发**要件引入流程，也不显示任何要件相关提示。案件列表页跳转、材料生成视图【生成文书】、分步生成视图【确认并编译文书】三个入口均遵守此规则。

在材料生成视图点击【生成文书】后、进入 AI 生成前：

1. 检查当前案件案由是否存在标准要件或用户自定义的“我的要件”
2. 若存在配置，先弹出「生成文书」前置选择弹框：
   - 标题：「生成文书」
   - 显示可用要件总数及分类统计（标准 / 我的）
   - 说明引入案由要件的作用：可让生成的文书更精确，系统会预生成参考答案，用户可在下一步修改
   - 黄色时间提示：引入要件后将增加答案预生成与整合步骤，整体生成时间可能会稍长
   - 底部左侧为【引入案由要件】（次按钮），右侧为【直接生成】（蓝色主按钮）
3. 用户选择：
   - **直接生成**：关闭弹框，仅使用已选材料生成
   - **引入案由要件**：关闭前置弹框，进入「引入案由要件」弹框
4. 「引入案由要件」弹框：
   - 标题：「引入案由要件」
   - 默认已勾选所有可用要件（标准要件 / 我的要件），用户可手动取消不需要的要件
   - 底部为【取消】和【引入要件并生成】（蓝色主按钮）
   - 若用户未勾选任何要件即点击【引入要件并生成】，系统提示"请先勾选要引入的要件"
5. 点击【引入要件并生成】后进入答案确认页：
   - 系统根据每个已勾选要件的问题**AI 预生成参考答案**
   - 用户可对答案进行修改、删除；如需新增自定义要件，点击弹窗内的「管理我的要件」进入 `pages/my-elements.html` 维护
   - 每个要件仅包含一个问题
6. 点击【确认并生成】后，将问题及答案作为生成上下文传入模型，最终文书保持原有文书形态，不直接展示问答内容
7. 若案由无配置要件，不弹窗，直接进入生成流程
8. **材料生成视图**与**分步生成视图**点击最终生成前均执行上述引入要件流程
9. **案件列表页**点击行内【生成文书】并在弹框中点击【开始生成】后，跳转 `case-files.html?source=list&autoGen=1&autoIntroduceElements=1`，默认全选材料并自动引入该案由全部标准要件与我的要件（系统预生成答案），不再弹出选择/答案确认弹框，仅显示友好提示，随后直接生成文书
10. **案件详情页（材料生成视图）**点击【生成文书】后仍执行上述前置选择弹框流程，由用户决定是否引入要件
11. 案件列表页顶部提供【我的要件】入口（与「我的模板」「我的提示词」并列），跳转至 `pages/my-elements.html`；案件详情页「引入案由要件」弹框内仍保留「管理我的要件」链接，跳转至 `pages/my-elements.html?cause=当前案由`，页面加载后自动选中对应案由

#### 我的要件维护页面（pages/my-elements.html）

> ℹ️ **使用范围提醒**：此处维护的「我的要件」仅在生成「裁判文书」类文书时才会询问是否引入辅助生成；其他文书类型（庭审提纲、执行文书、材料总结等）不会触发要件引入。页面顶部以提示条形式展示此说明。

- 页面左侧为**案由树**（3 级结构，与新增案件案由选择器一致，来自 `causeTreeDataByOrg`），右侧为该案由下的个人自定义要件列表
- 左侧顶部提供**搜索框**：输入关键词实时过滤叶子案由，匹配项的父级自动展开
- 左侧支持**置顶**常用案由：hover 叶子案由显示图钉按钮，置顶后集中在树顶部「置顶」分组下（按业务系统分组存储 `localStorage.myPinnedCauses`）
- 顶部提供「法院 / 检察院 / 司法局」业务系统切换按钮组（与「我的模板」「我的提示词」一致），切换后左侧案由树随之刷新
- 从案件详情页或引入案由要件弹窗进入时，URL 携带 `cause` 参数，页面自动选中该案由（并展开其所在的大类/中类）并展示其我的要件
- 右侧仅展示「我的要件」，不再展示「标准要件」；标准要件在引入案由要件弹窗中只读展示
- 支持新增、编辑、删除我的要件：点击【新增我的要件】后在列表底部展开编辑表单，填写名称、说明、问题、适用案字后保存
- **案字适配**（v1.26）：选中案由后，右侧要件列表上方显示「适配案字」选择栏（多选标签，来自 `caseWordListByOrg[org]`），标记该案由适配哪些案字；不勾选 = 适配全部案字（通用）。存储于 `localStorage.myCauseCaseWords`（按业务系统 × 案由分组）。
- **要件级适用案字**（v1.26）：新增/编辑要件表单中包含「适用案字」多选标签（优先展示该案由已勾选的适配案字，若未勾选则展示业务系统全部案字）；不选 = 通用（该案由下所有案字适用）。存储于要件对象的 `caseWords` 字段。
- **运行时过滤**：文书生成时 `getAllElementPresets(cause, org, caseWord)` 调用 `filterElementsByCaseWord` 过滤用户自定义要件，返回 `caseWords` 包含该案字或为空（通用）的要件。

### 9.3 批量生成交互（勾选触发 → 全屏面板）

**触发路径**：勾选 ≥1 个案件 → 顶部浮现批量操作栏 → 点击「批量生成」→ cases.html 内切换到全屏批量面板

**全屏面板流程**（橙色主题 #ea580c）：

#### 阶段①：配置
```
面板内容：
├─ 顶部：已选案件清单（显示案件名称，可移除单个，可清空）+ 【返回案件列表】
│   └─ 解析预检：存在 解析失败材料的案件名称后显示黄色「解析异常」徽标
├─ 解析预警面板（仅当存在 解析异常案件时显示）：
│   ├─ 警告文案：「N 个案件存在 解析失败的材料」+ 案件名称列表
│   └─ 策略选择（两个按钮，默认选中「跳过异常案件」）：
│       ├─ 跳过异常案件：批量执行时自动跳过这些案件，标记为「跳过」
│       └─ 仅用已识别材料生成：不跳过，使用该案件中已成功识别的材料生成文书
├─ 配置区：
│   ├─ 文书类型（下拉，按业务系统区分）
│   ├─ 文书模板（下拉，根据文书类型联动过滤，展示内置模板与「我的模板」，我的模板名称后追加「（我的）」标识）
│   ├─ 生成模式说明："系统将根据单个案件全部材料的预估 Token 数自动选择生成方式：未超过当前模型上下文限制时使用材料生成；超过限制时将自动跳过该案并记录失败原因，您可在批量任务结束后进入案件详情页单独处理。"
│   └─ 提示词（textarea，可选，含内置模板标签）
└─ 【开始批量生成】主按钮
```

#### 阶段②：队列执行中
- 顶部：批量进度总览（已完成/总数 + 已用时计时器）
- 队列列表：每个案件一行，状态 pending / current / done
- 串行执行，逐个处理；每个案件执行时根据该案件全部材料的预估 Token 数自动判断：
  - 未超限时：使用材料生成
  - 超限时：自动跳过该案并标记为失败，失败原因记录「案件材料超过当前模型上下文限制（预估 X / 上限 Y tokens），请进入案件详情页使用分步生成」；批量任务不中断，继续处理下一个案件

#### 阶段③：完成统计
- 统计卡片：案件总数 / 成功数 / 总字数 / 总耗时
- 操作：【一键打包下载】【选择性下载】【重试失败的】【新建批量任务】
- 结果明细列表：失败项除显示失败原因外，额外提供【去处理】按钮，点击新标签页打开 `case-files.html?caseId=xxx`，由用户在案件详情页手动使用分步生成

**返回规则**：全屏面板顶部「← 返回案件列表」→ 切回 cases.html 列表视图，保留原勾选状态

### 9.4 状态联动与边界

| 场景 | 行为 |
|------|------|
| 未勾选案件时 | 浮动批量操作栏不显示，无独立「批量生成」入口按钮 |
| 快速生成抽屉打开时勾选案件 | 抽屉保持，不影响 |
| 批量生成全屏面板执行中点「返回」 | 二次确认「任务正在执行，离开将停止？」（原型仅提示） |
| 快速生成完成关闭抽屉 | 案件列表刷新状态，可在「历史文书」弹窗查看生成结果 |
| 点击文件数量列 | 打开 文件解析状态弹窗，显示已完成/未完成文件列表，支持重新解析 |
| 解析异常提示 | 当案件存在 文件解析异常（非全部 done）时，文件数量列显示「正常数量/总数量」（如 `2/3`）+ 黄色背景标签 + 「解析异常」文字 badge；hover 显示 tooltip「存在 X 个材料文件解析异常，点击查看」；点击打开 解析弹窗 |
| 案件列表空状态 | 当某业务系统下暂无案件时，空状态区域展示「新建案件」「查看示例」两个引导入口（「同步案件」为预留入口，接口对接后恢复）；搜索/筛选结果为空时仅展示简单提示。详见《案件列表空状态引导 PRD》|

### 9.5 文书精修交互（v1.10 新增）

**触发路径**：
- 快速生成抽屉结果页 → 点击【文书精修】按钮
- 案件列表 → 查看文书弹窗 → 单个文书操作区 → 点击【文书精修】按钮
- 案件详情页 → 右栏「生成结果」面板 → 点击【文书精修】按钮

**交互流程**：
```
点击【文书精修】
  ├─ 案件详情页生成结果：将当前文书内容写入 `localStorage`，跳转 `chat.html?refine=1`
  ├─ 其他入口：打开「文书精修」弹窗/抽屉
  ├─ 左侧：多轮对话区
  │   ├─ 系统提示："请描述您希望如何调整这份文书"
  │   ├─ 用户输入修改意见 → 点击发送
  │   ├─ AI 回复：确认修改点并给出建议
  │   └─ 支持多轮追问，直至用户满意
  ├─ 右侧：版本对比区
  │   ├─ 【初稿】Tab：展示原始生成的文书内容
  │   └─ 【修订稿】Tab：展示根据多轮对话调整后的文书内容
  ├─ 用户点击【生成修订稿】
  │   └─ AI 基于对话历史生成修订稿，自动保存到该文书的 versions 中
  └─ 用户可选择【保存修订稿】【继续对话】【取消】
```

**数据规则**：
- 每个文书对象保存 `versions` 数组，至少包含 `original`（初稿）版本
- 精修后新增 `revised` 版本，记录修订时间、对话消息快照
- 初稿与修订稿均支持预览和下载

- 顶部含搜索框，支持按文书标题或案件名称搜索

**交互行为**：
```

  ├─ 全屏面板从右侧滑入
  ├─ 按生成时间倒序排列文书
  ├─ 每条文书右侧显示操作按钮：查看、文书精修、重新生成、下载、删除
  │   ├─ 查看：跳转 document-detail.html?caseId=...&docId=...，左侧 1/4 展示案件材料树，右侧 3/4 展示文书内容
  │   ├─ 文书精修：将文书内容写入 refineContext，新窗口打开 chat.html?refine=1 进入多轮对话精修

### 9.7 业务系统切换交互（v1.2 新增，v1.10 顺延编号）

> 设计原则：系统定位为面向检法司的泛化AI平台，通过配置化实现一套代码适配法院、检察院、司法局业务。

**切换入口**：页面顶部操作栏左侧，业务系统切换按钮组（法院 / 检察院 / 司法局）

**切换行为**：
```
点击切换按钮 → 触发 switchBusinessSystem(type)
  ├─ 更新当前业务系统标识
  ├─ 更新按钮激活状态（active样式）
  ├─ 更新页面标题（如"法院审判业务"→"检察院公诉业务"）
  ├─ 重新渲染统计卡片（标签、数字、图标）
  ├─ 重新渲染案件列表（案号、案由、当事人称谓、承办人称谓、状态文本）
  ├─ 更新表头「当事人」列标签（原告/被告 → 犯罪嫌疑人/被害人 → 申请人/被申请人）
  ├─ 更新状态筛选器下拉选项（待开庭 → 审查起诉 → 待调解）
  └─ 关闭打开的抽屉/面板（快速生成抽屉、批量生成面板）
```

**业务系统差异映射表**：

| 维度 | 法院系统 | 检察院系统 | 司法局系统 |
|------|---------|-----------|-----------|
| 页面标题 | 法院审判业务 | 检察院公诉业务 | 司法局调解业务 |
| 当事人称谓 | 原告/被告 | 犯罪嫌疑人/被害人 | 申请人/被申请人 |
| 承办人称谓 | 法官 | 检察官 | 调解员 |
| 状态 - pending | 待开庭 | 审查起诉 | 待调解 |
| 状态 - ongoing | 审理中 | 已起诉 | 调解中 |
| 状态 - closed | 已结案 | 不起诉 | 已办结 |

|------|------|
| 多选 | 每行文件前含复选框，表头复选框可全选/取消全选 |
| 批量删除 | 勾选文件后，顶部工具栏显示「批量删除」按钮 |
| 批量发送至对话框 | 勾选文件后，底部浮动栏显示「发送至对话框」按钮 |
| 预览 | 文件行常驻预览按钮，也可点击文件名称在新标签页打开预览 |
| 下载 | 文件行常驻下载按钮，点击后浏览器下载该文件 |
| 更多 | 收起编辑名称、设置分类、删除入口；删除需二次确认，仅删除该材料 |
| 发送至对话框 | 通过底部「选择文件」或勾选后批量加入对话框，不再在文件行常驻 |

### 14.4a 文件问答对话框

页面材料列表上方提供固定问答输入区：

- **已选文件**：以标签形式展示已加入对话框的文件，点击标签上的「×」可移除；多个文件时折叠为「xxx 等 N 个文件」。
- **问题输入**：文本域支持输入法律问题，按 `Ctrl/Shift + Enter` 换行，按 `Enter` 发送。
- **选择文件**：点击「选择文件」按钮可将文件列表中选中的文件批量加入对话框；未勾选时点击则提示先选择文件。
- **发送**：点击右侧发送按钮，将已选文件与问题组合提交，模拟 AI 根据文件内容返回答案。
- **清空**：发送成功后自动清空问题与已选文件。

### 14.5 删除范围确认

无论是单个删除还是批量删除，点击删除后均弹出确认弹窗，提供两种范围：

- **仅删除原始材料（保留已生成文书）**：仅移除选中的案件材料文件，已生成的文书不受影响。
- **同时删除原始材料及已生成文书**：移除选中材料，并清空该案下所有已生成文书。

用户选择范围后点击「删除」执行；删除完成后自动刷新案件列表的文件数量。

### 14.6 批量删除流程

```
勾选需要删除的材料（可单选/多选/全选）
  ├─ 工具栏显示「已选 X 项」与「批量删除」按钮
  ├─ 点击「批量删除」
  ├─ 弹出删除范围确认弹窗
  │   ├─ 选择「仅删除原始材料」或「同时删除文书」
  │   └─ 点击「删除」执行
  ├─ 从案件文件列表中移除选中项
  ├─ 更新案件 fileCount 与 updatedAt
  ├─ 如选择删除文书，清空案件 documents 数组
  └─ 返回案件列表自动刷新
```

### 18.2 入口

| 类型 | 入口 |
|------|------|
| 单个删除 | 案件列表操作栏 → 删除图标按钮（🗑️） |
| 批量删除 | 勾选案件后，顶部浮动批量操作栏 → 「批量删除」按钮 |

- **仅删除原始材料（保留已生成文书）**：清空选中案件的 `files` 材料列表，案件本身及已生成文书保留在系统中。
- **删除案件（原始材料及已生成文书均删除）**：将选中案件从当前业务系统案件列表中移除。

### 18.4 交互流程

```
点击删除按钮
  ├─ 弹出删除范围确认弹窗
  │   ├─ 选择「仅删除原始材料」或「删除案件」
  │   └─ 点击「删除」执行
  ├─ 若选择仅删除材料：

  │   ├─ fileCount 置为 0

  ├─ 若选择删除案件：
  │   ├─ 从当前业务系统 cases 数组中移除选中案件
  │   └─ 清空已选案件勾选状态
  └─ 重新渲染案件列表并提示结果
```

### 18.5 边界规则

- 批量删除仅作用于当前业务系统可见的已选案件。
- 删除案件后，关联的历史文书弹窗、解析弹窗等不再展示该案件数据。
- 操作完成后显示通知提示删除结果。

## 第二十章 管理后台 - 文书模板管理

> 设计原则：模板与「文书类型 + 案由」双重关联；数据结构升级为对象；用户侧生成文书时按当前案件 cause 自动过滤模板；支持启用/停用状态控制。

## 第二十五章 管理后台 - workflow 配置（挂在文书类型下）

> 设计原则：workflow 是系统内部配置，**对用户完全不可见**；用户侧只看到「材料生成 / 分步生成」两个 tab 与带出的步骤序列，不感知 workflow 概念。
> workflow 的本质是「节点流程」配置容器，按「业务系统 × 文书类型」分组，包含两种类型（v1.29 简化命名）：
> - **展示型**（type='step'）：含人工交互节点（步骤序列），用户在分步生成 tab 中按步骤逐个确认材料与内容，最终编译为完整文书
> - **不展示型**（type='material'）：无人工交互节点，输入参数（材料 + 模板 + 提示词）后直接输出文书结果，用于材料生成 tab
> 数据持久化：`localStorage.adminWorkflows`（按业务系统分组），用户侧 `getWorkflowsForDocType` 优先读此 key，为空回退到 case-files.js const `stepConfigsByOrg`。
> 与生成策略的关系：workflow **不绑定生成策略**。案件列表页由 token 自动决定模式；案件详情页用户选 tab；用户选「分步生成」时按案字匹配展示型 workflow 取其 steps；用户选「材料生成」时按案字匹配不展示型 workflow 取其配置（无 steps）。

### 25.1 配置入口（内联于文书类型管理页）

- 不单独开模块、不增加菜单项
- 在文书类型管理页表格中，每个类型行新增「展开/折叠」按钮（行首 `fa-chevron-right` / `fa-chevron-down`）
- 点击展开后，在类型行下方显示该类型下的 workflow 子表格
- workflow 配置区域标题：「{类型名} 的 workflow」+「新增 workflow」按钮

    └─ 点击取消
            └─ 关闭模态框
```

### 25.5 删除 workflow 交互

- 点击「删除」→ 二次确认弹窗
- 内置 workflow 删除 = 移除自定义覆盖（恢复内置默认）
- 自定义 workflow 删除 = 直接移除
- **删除前校验**：若该类型下某类型（展示型/不展示型）的 workflow 仅剩此一个，禁止删除并提示「每个类型至少需保留 1 个展示型 workflow」或「每个类型至少需保留 1 个不展示型 workflow」

### 25.6 步骤编辑器交互（仅展示型）

- 步骤列表为可编辑的有序列表，每行包含：步骤 id、步骤标题、图标（从预设图标库选）、操作按钮（上移 / 下移 / 删除）
- 「上移」/「下移」调整步骤顺序，列表实时重排
- 「删除」移除该步骤（至少保留 1 个，否则禁用删除按钮）
- 「+ 添加步骤」在列表底部追加一行空步骤
- 步骤 id 用于代码侧 `stepData[stepId]` 的键，需保证同 workflow 内唯一
- 不展示型 workflow 不显示步骤编辑器

### 25.7 用户侧联动

- 案件列表页生成文书：由 token 自动决定模式（现状不变），不涉及 workflow 选择
- 案件详情页用户选「分步生成」tab 时：
  1. **文书类型下拉仅展示存在展示型 workflow 的类型**（v1.29 新增；自然收敛为裁判文书、庭审提纲等），无展示型 workflow 的类型不出现
  2. 系统从案件 `caseNumber` 中提取案字（正则匹配 `民初/民终/民再/刑初...`）
  3. 调用 `getWorkflowsForDocType(org, docTypeKey, 'step')` 获取该类型下所有**展示型** workflow
  4. 按案字匹配默认展示型 workflow（匹配 caseWords → 兜底 caseWords=[] → 第一个）
  5. **步骤方案下拉**（仅当该类型下有 2 个及以上展示型 workflow 时显示）：
     - 位于分步配置区，文书类型与文书模板之间
     - 选项为 workflow 的业务化名称（如「一审民事判决步骤」「二审民事判决步骤」），**不出现"workflow"一词**
     - 默认选中案字自动匹配的展示型 workflow
     - 用户可手动切换，切换后重新加载该 workflow 的步骤序列并重置步骤状态
     - 仅 1 个展示型 workflow 时不显示此下拉（无切换需求）
  6. 步骤列表渲染所选展示型 workflow 的 steps
- 案件详情页用户选「材料生成」tab 时：
  1. 系统从案件 `caseNumber` 提取案字
  2. 调用 `getWorkflowsForDocType(org, docTypeKey, 'material')` 获取该类型下所有**不展示型** workflow
  3. 按案字匹配默认不展示型 workflow（匹配 caseWords → 兜底 caseWords=[] → 第一个），用于确定使用哪一套材料生成流程
  4. 不展示型 workflow 无步骤序列，用户侧仅感知「材料 + 模板 + 提示词 → 生成文书」的表单交互，不暴露 workflow 概念
  5. 仅 1 个不展示型 workflow 时不显示任何切换入口（无切换需求）
  6. **文书类型下拉展示全量类型**（用于匹配模板与提示词）

### 25.8 与其他模块的关系

| 模块 | 关系 |
|------|------|
| 文书类型管理（第24章） | workflow 挂在文书类型下，类型删除时同步清理该类型下所有 workflow（含展示型与不展示型） |
| 文书模板管理 / 提示词管理 | 无直接关系，模板/提示词仍挂文书类型下，不按 workflow 区分 |
| 案件详情页分步生成 | `getStepsConfigForDocType` 按案字匹配**展示型** workflow，取其 steps；**文书类型下拉仅展示有展示型 workflow 的类型** |
| 案件详情页材料生成 | `getMaterialWorkflowByCaseWord` 按案字匹配**不展示型** workflow，仅用于流程选择，不暴露给用户；文书类型下拉展示全量类型 |
| 生成策略 | workflow 不绑定策略；策略仍由 token（列表页）或用户选 tab（详情页）决定 |
