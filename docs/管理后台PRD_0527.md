# 二、产品概述

## 2.1 产品背景

AI辅助办案系统管理后台是为系统管理员提供的综合管理界面。作为AI法官助理的核心支撑模块，管理后台承担用户管理、知识库维护、案由配置、风控审计、系统配置等关键职能，确保系统安全、合规、高效运行。

## 2.2 目标用户

- **超级管理员**：负责系统整体配置、用户管理、安全审计
- **系统管理员**：负责用户管理、基础配置、系统监控
- **业务管理员**：负责案由、知识库等业务数据维护

## 2.3 产品定位

管理后台是AI辅助办案系统的核心支撑模块，覆盖以下管理职能：

- 用户全生命周期管理（创建、禁用、角色绑定、用量统计）
- 系统初始化配置（部署时一次性配置，配完锁定）
- 业务数据维护（案由分类体系、知识库分类与文档）
- 风控与审计管理（敏感词库、审计日志）
- 系统运行报告（周报/月报，支持导出PDF）

所有管理操作遵循基于角色的访问控制（RBAC），审计日志不可篡改。

### 2.4 功能审计三原则

每新增一个管理后台功能前，必须通过以下三项检查：

| 原则 | 检查问题 | 判定 |
| :--- | :--- | :--- |
| 频率检查 | 这个操作一个月会做超过一次吗？ | 不会 → 不需要管理后台页面，走配置文件或初始化脚本 |
| 角色检查 | 法院IT有这个专业能力操作吗？ | 不会（如"编辑Prompt"） → 不需要暴露给他 |
| 合规检查 | 不做这个，会被纪检/等保/合规卡住吗？ | 会 → 必须做 |

### 4.1.2 核心指标卡片

| 指标 | 说明 | 数据来源埋点 | 变化趋势 |
| :--- | :--- | :--- | :--- |

### 4.1.3 各模块今日任务数（新增）

在核心指标卡片下方，展示各智能体模块今日任务数概览：

| 模块 | 说明 | 数据来源埋点 |
| :--- | :--- | :--- |
| 文书生成 | 今日文书生成任务数 | agent_doc.task.start (COUNT WHERE date=today) |
| 庭审提纲 | 今日庭审提纲任务数 | agent_trial.task.start (COUNT WHERE date=today) |
| 法条适用 | 今日法条适用任务数 | agent_law.task.start (COUNT WHERE date=today) |
| 文书评查 | 今日文书评查任务数 | agent_review.task.start (COUNT WHERE date=today) |
| 知识问答 | 今日知识问答次数 | agent_qa.question.submit (COUNT WHERE date=today) |

展示形式：6个小卡片横排，每个卡片含模块图标、名称、今日任务数、较昨日变化趋势。

### 4.1.4 快捷操作区

- 添加用户 → 跳转用户管理

- 搜索框：按用户名、部门搜索
- 角色筛选：全部/超级管理员/系统管理员/业务管理员/普通用户
- 部门筛选：全部/具体部门
- 状态筛选：全部/正常/禁用

### 4.2.4 单用户操作

| 字段 | 类型 | 必填 | 说明 |

## 4.3 系统运行报告

**页面路径**：`pages/admin/system-report.html`

### 4.3.1 功能概述

为法院领导汇报提供系统运行情况的静态报告，支持按周/月生成报告并导出PDF。不做实时数据看板，不做交互式图表。

> **定位变更说明**：原"数据仪表盘"定位为实时数据看板，但G端内网系统不存在DAU驱动的运营需求，法院领导需要的是可导出的汇报材料，而非实时折线图。按频率检查原则，领导看报告是周/月频次，不需要实时刷新。

### 4.3.2 报告类型

| 报告类型 | 生成周期 | 说明 |
| :--- | :--- | :--- |
| 周报 | 每周一自动生成 | 覆盖上周数据 |
| 月报 | 每月1日自动生成 | 覆盖上月数据 |
| 自定义报告 | 手动触发 | 选择时间范围生成 |

### 4.3.3 报告内容

报告以文档形式呈现，包含以下章节：

**一、系统运行概况**

| 指标 | 说明 |
| :--- | :--- |
| 报告周期 | 本周/本月 |
| 系统运行天数 | 周期内系统正常运行天数 |
| AI任务总数 | 周期内所有智能体任务总数 |
| 文书生成采纳率 | AI输出被法官直接采用的比例 |
| 平均案件处理时长 | 从收案到结案的平均耗时 |

**二、各模块使用情况**

| 模块 | 任务数 | 采纳率 | 较上期变化 |
| :--- | :--- | :--- | :--- |
| 文书生成 | xx | xx% | ↑/↓ |
| 庭审提纲 | xx | xx% | ↑/↓ |
| 法条适用 | xx | xx% | ↑/↓ |
| 文书评查 | xx | xx% | ↑/↓ |
| 知识问答 | xx | — | ↑/↓ |

**三、部门使用排名**

按部门统计AI使用次数排名（Top5），含部门名称、使用次数、较上期变化。

**四、异常与风险**

| 指标 | 说明 |
| :--- | :--- |
| AI生成失败次数 | 周期内生成失败总数 |
| 敏感词拦截次数 | 周期内风控拦截总数 |
| 系统异常事件 | 周期内系统异常事件列表 |

### 4.3.4 报告操作

| 操作 | 说明 |
| :--- | :--- |
| 查看报告 | 在线预览报告内容 |
| 导出PDF | 导出为PDF文件，文件名格式：`系统运行报告_{类型}_{周期}.pdf` |
| 历史报告 | 查看和导出历史生成的报告 |

### 4.3.5 数据来源

所有数据来源于埋点系统，报告生成时自动聚合计算，不支持手动编辑报告内容。

### 4.4.2 文档管理

**页面路径**：`pages/admin/knowledge-documents.html`

#### 功能概述

管理知识库中的文档，支持上传、状态管理、删除等操作。文档经OCR识别后可被AI检索引用。

#### 知识库范围（V1.0）

- **法条库**：现行有效法律法规及司法解释，含版本、效力状态信息
- **历史案例库**：脱敏后的本院/上级法院裁判文书
- **内部审判指引**：可选，需管理员配置权限

#### 文档列表

**列表字段**：

| 字段 | 说明 |
| :--- | :--- |
| 文档名称 | 文件名称 |
| 所属知识库 | 知识库名称 |
| 文件类型 | PDF/Word/TXT/Markdown |
| 文件大小 | 文件大小 |
| 状态 | 上架/下架/处理中/解析失败 |
| 上传时间 | 上传日期 |
| 操作 | 编辑、上架/下架、删除 |

#### 文档上传

**上传方式**：

- 点击"上传文档"按钮
- 支持拖拽上传

**上传弹窗**：

```
┌─────────────────────────────────────┐
│           上传文档到知识库           │
├─────────────────────────────────────┤
│                                     │
│           ┌─────────────┐           │
│           │     📤      │           │
│           │ 点击或拖拽  │           │
│           │ 文件到此区域 │           │
│           └─────────────┘           │
│                                     │
│    支持格式: PDF, Word, TXT, MD     │
│    单个文件最大50MB                 │
│                                     │
├─────────────────────────────────────┤
│  选择目标知识库: [下拉选择 ▼]       │
├─────────────────────────────────────┤
│  上传文件列表:                      │
│  ┌─────────────────────────────┐    │
│  │ 📄 文件1.pdf  [进度条] ✓    │    │
│  │ 📄 文件2.docx [进度条] ⏳   │    │
│  └─────────────────────────────┘    │
├─────────────────────────────────────┤
│         [取消]        [开始上传]    │
└─────────────────────────────────────┘
```

**上传处理流程**：

1. 选择文件→格式校验→显示预览
2. 选择目标知识库
3. 点击上传→显示进度条
4. OCR识别处理→索引构建
5. 上传完成→返回文档列表

**支持格式及图标颜色**：

| 格式 | 图标颜色 |
| :--- | :--- |
| PDF | 红色 |
| Word/Doc/Docx | 蓝色 |
| TXT | 灰色 |
| Markdown | 橙色 |

**文件大小限制**：

- 单个文件最大：50MB
- 批量上传：最多10个文件

#### 文档状态管理

**法条文档**：

- 支持"有效/废止"标记
- 废止法条不参与AI推荐和检索
- 状态变更需二次确认

**案例文档**：

- 支持"上架/下架"操作
- 下架案例不参与类案推荐

**异常处理**：

- 上传未脱敏或包含违规内容的文档，系统应告知风险并拒绝入库
- 文件解析失败时，状态标记为"解析失败"，支持重新解析

#### 文档删除

- 二次确认弹窗
- 提示删除后不可恢复
- 删除后对应的OCR文本和索引同步清除

**页面路径**：`pages/admin/cause-management.html`

### 4.5.1 功能概述

管理系统案由分类体系，支持三级案由层级结构。案由数据供AI案由明鉴模块和Chat页面用户选择使用。

### 4.5.2 统计卡片

| 指标 | 说明 |
| :--- | :--- |
| 一级案由 | 一级分类数量 |
| 二级案由 | 二级分类数量 |
| 三级案由 | 三级分类数量 |
| 案由总数 | 全部案由合计 |

### 4.5.3 案由树形结构

**层级定义**：

- **一级案由**：大类（如民事案由、刑事案由）
- **二级案由**：中类（如合同纠纷、侵权责任纠纷）
- **三级案由**：具体案由（如买卖合同纠纷、离婚纠纷）

│   └── 产品责任纠纷

### 4.5.8 案由状态管理（上线/下线）

**功能描述**：每个案由节点支持"上线/下线"状态切换，控制该案由在前端是否可见可用。

**状态定义**：

| 状态 | 说明 | 前端可见性 |
| :--- | :--- | :--- |
| 已上线 | 案由已发布，可供前端用户选择使用 | 可见、可选 |
| 未上线 | 案由未发布或已下线，仅管理后台可见 | 不可见、不可选 |

**操作规则**：

- **上线操作**：点击"上线"按钮，案由状态切换为"已上线"，前端即时生效
- **下线操作**：点击"下线"按钮，需二次确认弹窗提示："下线后，前端用户将无法看到和选择该案由，已关联该案由的案件在前端也将不可见，确认下线？"，确认后状态切换为"未上线"
- **批量操作**：支持对一级/二级案由批量上线/下线，操作时联动其下所有子案由状态同步变更
- **默认状态**：新建案由默认为"未上线"状态，需管理员手动上线后才对前端可见

**数据结构**：

案由数据中每个节点增加 `status` 字段：

```json
{
  "name": "买卖合同纠纷",
  "status": "online",
  "children": []
}
```

- `status` 取值：`"online"`（已上线）/ `"offline"`（未上线，默认）
- 上线/下线操作时同步更新 `adminCauseData` 和 `causeData`

**数据流向**：

```
管理后台（案由管理页面）
  ├── 新增/编辑案由 → 写入 adminCauseData（含status字段）
  ├── 上线/下线操作 → 更新 adminCauseData 中对应节点status
  └── 同步写入 causeData → 前端页面读取
        ├── Chat页面案由选择器 → 仅加载 status=online 的案由
        ├── 案件页面案由筛选器 → 仅加载 status=online 的案由
        └── 首页案由推荐 → 仅展示 status=online 的案由
```

### 4.5.9 边界场景与异常数据处理

**场景1：下线案由下的案件在前端的可见性**

| 场景 | 规则 | 说明 |
| :--- | :--- | :--- |
| 案由下线后，该案由下的已有案件 | 前端不可见、不可搜 | 案件列表和搜索结果均需过滤掉关联案由为"未上线"的案件 |
| 案由下线后，用户搜索案件关键词命中下线案由的案件 | 不返回结果 | 搜索时需校验案件关联案由的上线状态 |
| 案由重新上线后，之前的案件 | 自动恢复可见 | 无需手动操作，案件随案由上线自动恢复展示 |
| 案由下线后，案件详情页的直接访问 | 提示"该案件关联案由已下线" | 防止通过URL直接访问 |

**场景2：数据一致性保障**

| 异常情况 | 处理策略 |
| :--- | :--- |
| 案件的案由字段为空 | 前端不展示该案件，管理后台标记为"案由缺失"待处理 |
| 案件的案由在案由树中不存在（被删除） | 前端不展示该案件，管理后台标记为"案由异常"待处理 |
| localStorage数据被清空 | 前端使用内置默认案由数据兜底，管理后台提示"数据异常，请重新配置" |
| causeData与adminCauseData不同步 | 以adminCauseData为准，管理后台保存时强制同步写入causeData |

**场景3：层级联动规则**

- 一级案由下线 → 其下所有二级、三级案由自动下线（前端均不可见）
- 二级案由下线 → 其下所有三级案由自动下线
- 一级案由上线 → 不自动上线子案由，需逐个手动上线
- 删除案由 → 已关联该案由的案件标记为"案由异常"，前端不展示

**默认预置参数模板**（新建模型时按模型分类自动填充默认参数）：

##### 思考模式配置块（thinkingMode，字段类型：object）

"思考模式"为专用配置块，以独立卡片形式展示在模型参数区域顶部，不作为动态键值对行，而是结构化的 object 字段：

| 字段 | 类型 | 必填 | 默认值 | 说明 |
| :--- | :--- | :--- | :--- | :--- |
| enabled | Boolean | 是 | false | 是否启用思考模式（深度推理） |
| display_style | String | 否 | "collapsible" | 思考过程展示方式：collapsible（可折叠，默认收起）/ inline（内联展示） |
| token_limit | Number | 否 | 8192 | 思考模式最大思考Token数 |
| filter_english | Boolean | 否 | true | 是否过滤思考输出中的英文内容 |
| english_filter_mode | String | 否 | "remove" | 英文过滤模式：remove（移除英文片段）/ translate（翻译为中文） |

**交互说明**：

- enabled=false 时，其余字段置灰不可编辑
- enabled=true 时，展开所有配置项
- display_style 选项：
  - `collapsible`：思考过程以可折叠区块展示，默认收起，用户可点击展开查看推理过程
  - `inline`：思考过程直接内联展示在回复内容中
- filter_english=true 时，显示 english_filter_mode 选项
- filter_english=false 时，english_filter_mode 置灰

**思考输出英文过滤规则**（filter_english=true时生效）：

| 规则 | 匹配逻辑 | 处理方式 |
| :--- | :--- | :--- |
| 连续英文句子 | 连续3个以上英文单词的片段 | 按 english_filter_mode 处理（移除或翻译） |
| 英文术语夹杂 | 单个英文词前后有中文 | 保留不动（如"根据PDF文件"、"调用API接口"） |
| 纯英文段落 | 整段无中文字符 | 按 english_filter_mode 处理 |
| 合法英文白名单 | 常见法律术语缩写、当事人英文名、证据编号 | 保留不动（如"DNA鉴定"、"A公司"） |

**英文过滤分层治理方案**：

| 层级 | 策略 | 说明 | 效果 |
| :--- | :--- | :--- | :--- |
| 第1层 | 系统提示词约束 | 在模型system prompt中强制约定"必须使用中文思考和回复，禁止使用英文" | 从源头减少，解决80% |
| 第2层 | 思考输出后处理 | filter_english配置项控制的正则规则过滤 | 精准清洗漏网的英文片段 |
| 第3层 | 展示层兜底 | display_style=collapsible默认折叠思考过程，用户不展开则无感 | 兜底保障 |

**数据结构**：

```json
"thinkingMode": {
  "enabled": true,
  "display_style": "collapsible",
  "token_limit": 8192,
  "filter_english": true,
  "english_filter_mode": "remove"
}
```

| 核采样阈值 | topP | 0.9 | 0~1 | 控制候选词范围 |
| 候选词数量 | topK | 50 | 1~100 | 候选词上限 |
| 最大生成长度 | maxTokens | 4096 | 1~128000 | 单次生成最大Token数 |
| 频率惩罚 | frequencyPenalty | 0 | -2~2 | 减少重复内容 |
| 存在惩罚 | presencePenalty | 0 | -2~2 | 鼓励话题多样性 |
| 停止序列 | stopSequences | [] | JSON数组 | 停止生成的标记序列 |

##### 其他配置组（options）

| 中文名称 | Key | 默认值 | 说明 |
| :--- | :--- | :--- | :--- |
| 是否流式输出 | stream | true | 流式输出提升用户等待体验 |
| 失败自动重试 | retryOnFailure | true | 调用失败是否自动重试 |
| 最大重试次数 | maxRetries | 2 | 重试次数上限 |
| 超时时间(秒) | timeout | 60 | 单次调用超时 |

### 4.9.3 法院模型授权

**功能描述**：按法院维度配置可使用哪些模型，以及各自的Token额度。支持法院层级关系（如中院采购、基层法院使用）。

**法院授权列表**：

| 字段 | 说明 |
| :--- | :--- |
| 法院名称 | 法院名称（如 南京市中级人民法院） |
| 法院层级 | 中院/基层法院 |
| 已授权模型 | 该法院可使用的模型列表（显示模型名称标签） |
| Token总配额 | 该法院的总Token额度（如 1000万tokens） |
| Token已用 | 已消耗Token量 |
| 剩余额度 | 剩余可用Token |
| 使用率 | 已用/配额 百分比，带进度条 |
| 状态 | 正常/超额停用 |
| 操作 | 配置、调整额度、用量详情 |

**法院筛选**：

- 搜索框：按法院名称搜索
- 层级筛选：全部/中院/基层法院
- 状态筛选：全部/正常/超额停用

**配置法院模型权限**：

| 字段 | 类型 | 必填 | 说明 |
| :--- | :--- | :--- | :--- |
| 选择法院 | 下拉 | 是 | 选择授权的法院 |
| 可用模型列表 | 多选 | 是 | 从系统已启用的模型中选择 |
| Token配额 | 数字 | 是 | 该法院的总Token额度 |
| 额度周期 | 单选 | 是 | 按月/按年/永久 |
| 额度重置时间 | 日期 | 条件必填 | 按月/按年时必填 |
| 启用状态 | 开关 | 是 | 可手动停用 |

**调整额度**：

- 支持追加或减少Token配额
- 记录调整原因和调整
- 调整历史可追溯

**特殊规则**：

- 基层法院的配额自动从所属中院的采购总额中扣减（可选，由管理员配置是否启用层级关联）
- 某法院Token用尽后，系统自动暂停该法院的AI调用服务，并提示管理员

### 4.9.4 Token用量统计

**功能描述**：多维度查看各法院、各模型的Token消耗情况，支持时间范围筛选和导出。

**统计维度**：

| 维度 | 说明 |
| :--- | :--- |
| 按法院 | 各法院的Token消耗排名 |
| 按模型 | 各模型的Token消耗分布 |
| 按时间 | 日/周/月/自定义时间段的消耗趋势 |

**统计指标**：

| 指标 | 说明 |
| :--- | :--- |
| 总Token消耗 | 统计周期内所有法院消耗总和 |
| 法院Token消耗 | 单法院消耗量及排名 |
| 模型Token消耗 | 各模型分别消耗量 |
| 调用次数 | 各法院/模型的API调用次数 |
| 平均Token/次 | 单次调用的平均Token消耗 |
| 剩余总配额 | 所有法院剩余额度合计 |

**展示形式**：

- **概览卡片**：总Token消耗、调用次数、活跃法院数、超限告警数
- **趋势折线图**：按时间维度的Token消耗趋势
- **柱状图**：各法院/各模型的Token消耗排名Top10
- **明细表格**：支持按法院、模型、时间段筛选，支持导出Excel

**明细表格字段**：

| 字段 | 说明 |
| :--- | :--- |
| 时间 | 统计时段（日/月） |
| 法院名称 | 调用法院 |
| 模型名称 | 使用的模型 |
| 调用次数 | 该时段调用次数 |
| Token消耗 | 该时段Token消耗 |
| 平均Token/次 | 单次平均消耗 |

### 4.9.5 用量告警

**功能描述**：当法院Token使用量接近或超过阈值时，自动触发告警。

**告警规则配置**：

| 配置项 | 默认值 | 说明 |
| :--- | :--- | :--- |
| 预警阈值 | 80% | 使用率达到时发送提醒 |
| 超额停用 | 开启 | 达到100%时自动停用 |
| 通知方式 | 系统通知 | 预留：短信/邮件 |
| 通知对象 | 该法院管理员 | 可配置多名通知接收人 |

**告警记录列表**：

| 字段 | 说明 |
| :--- | :--- |
| 时间 | 告警触发时间 |
| 法院名称 | 触发告警的法院 |
| 告警类型 | 预警/超额/恢复 |
| 当前使用率 | 如 85% |
| 处理状态 | 已处理/未处理 |
| 操作 | 查看详情、追加额度、标记已处理 |

**告警处理**：

- 收到预警后，管理员可追加额度或提醒法院控制使用
- 超额停用后，需手动追加额度并重新启用
- 追加额度操作记录在操作日志中

### 4.9.6 与智能体编排平台的数据交互

**职责分工**：

| 职责 | 负责系统 |
| :--- | :--- |
| 模型列表维护 | 管理后台 |
| 法院模型授权 | 管理后台 |
| Token配额管理 | 管理后台 |
| 用量统计与展示 | 管理后台 |
| 模型技术接入与版本管理 | 智能体编排平台 |
| 单次调用的Token计数 | 智能体编排平台 |
| 调用性能监控（延迟、成功率） | 智能体编排平台 |

**数据流向**：

- 智能体编排平台每次调用模型后，上报Token消耗数据至管理后台
- 管理后台调用法院授权接口，查询该法院是否有权限调用某模型及剩余额度
- 智能体编排平台接收授权结果，额度不足时拒绝调用并返回提示

### 4.9.7 交互细节

**配额即将用尽的提醒**：

- 法院用户在使用AI功能时，若剩余Token不足20%，在界面顶部显示黄色提示条：“当前Token额度即将用尽，请联系管理员追加配额”
- 法院管理员登录管理后台时，若所辖法院存在额度不足20%的情况，在控制台显示告警卡片

**超额停用后的用户提示**：

- 法院用户尝试使用AI功能时，返回提示：“Token额度已用尽，AI服务暂时不可用，请联系管理员”
