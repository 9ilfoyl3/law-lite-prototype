基层民事法官 · 主要用户 案多人少 · 时间紧张 · 不擅长复杂配置 · 50 岁左右视力一般
E1 · 一键生成裁判文书 P0 核心
作为法官，我希望上传案件材料后系统自动解析并一步生成裁判文书初稿，流式输出让我感知在生成。
  • 前端不做 Token 估算，直接调 workflow
  • 默认加载全部要素（标准+自定义）
  • 流式输出 + 字数/进度提示
  • workflow 超限返回异常后展示提示
E2 · 复杂案件分步生成 P0 核心
作为法官，我希望对裁判文书按 6 步序列逐步生成，让我对中间环节有掌控感。
  • 仅裁判文书类型展示分步生成 Tab
  • 6 步硬编码：案件信息→原告诉请→被告答辩→争议焦点→事实认定→裁判结果
  • 手动逐步触发，选完材料不自动生成
  • 步骤依赖：步骤4选填前3步，步骤5/6必填前一步
  • 片段拼接产出完整文书
E3 · 案件状态追踪 P1 重要
作为法官，我希望在列表页一眼看清每个案件的解析状态与历史文书，不必进入详情就能判断下一步。
  • 材料数量列：解析中 spinner / 异常黄色徽章
  • 案件名称后蓝色文书数徽章（可点击打开历史文书）
  • 列配置默认最小列集（名称/更新时间/材料数量）
  • 不设独立状态字段，靠派生指标表达
E4 · 模板与提示词个性化 P1 重要
作为法官，我希望维护自己的模板和提示词并启用/停用，让文书更符合本庭风格。
  • 标准/我的模板下拉分组显示，"我的"徽章
  • 提示词按来源颜色区分 + 启用/停用
  • 提示词历史版本管理（最多 10 条，一键恢复）
  • 已移除全局"恢复默认"按钮
E5 · 批量生成与异步队列 P2 增强
作为法官，我希望一次勾选多个案件批量生成，配置阶段告知异常案件，执行阶段异步不阻塞。
  • 统一一种文书类型，模型字段只读
  • 配置阶段：解析异常案件黄色徽章 + 策略选项
  • 异步队列 + 进度反馈（顶部"批量任务"入口）
  • 队列满时阻止提交，提示剩余位置
  • workflow 超限标记 failed + 提示进详情页
E6 · 文书精修与版本管理 P2 增强
作为法官，我希望对已生成文书多轮对话式精修，并保留所有版本可回溯。
  • 精修独立页（左文书 + 右对话），新标签页打开
  • 每轮修改可撤销，保存为新版本不覆盖原文
  • 历史文书列表按时间倒序，查看/下载/删除
  • 重新配置回填最近版本配置
E7 · 引入要件（可选 Plus） P2 增强
作为法官，我希望文书生成时可选引入要件作为上下文，可 0 个可多个。
  • 本案要件入口在材料树顶部固定条
  • 弹框两步：选择要件 → 确认 AI 预生成答案
  • 三种来源：标准(蓝)/我的(绿)/个案(橙)
  • 个案要件(橙色标签) 默认勾选 + 答案预生成
  • 弹框内已去掉"管理我的要件"链接
  • 要件结果持久化到 localStorage（案件维度）
E8 · 案由案字管理关系 P1 重要
作为法官/管理员，我希望案字适配时只看到当前案由大类允许的案字，避免管理关系错乱。
  • 案由大类→案字白名单映射（民事→民初/民终/民再 等）
  • 一级/二级/三级案由均可触发白名单匹配（getCauseCategory）
  • 我的要件/管理后台要件管理：案字栏仅展示允许项
  • 已有不在白名单的案字标记"已禁用"（灰+删除线）
  • 历史数据保留显示，用户手动清理
