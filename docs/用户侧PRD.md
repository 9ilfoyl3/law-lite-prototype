# 二、产品概述

## 2.1 产品背景

AI辅助办案系统用户侧是面向基层检法司办案人员的核心办案辅助界面。系统运行在政法专网内，围绕"案件管理 → 材料组织 → 文书生成 → 个人配置"主链路，将 AI 能力以表单化、图形化方式嵌入法官/检察官/司法局工作人员的日常案头工作，降低文书撰写与材料梳理的时间成本。

用户侧与管理后台共同构成完整产品：管理后台负责系统级配置（案由、文书类型、workflow、标准要件、模型、模板、提示词），用户侧负责消费这些配置并完成实际办案操作。用户侧同时提供"我的要件 / 我的模板 / 我的提示词"三个个人级配置入口，与系统/管理后台数据分层并存。

## 2.2 目标用户

| 角色 | 主要业务 | 使用场景 |
| :--- | :--- | :--- |
| 法官 / 法官助理 | 民事/刑事/行政审判、执行 | 裁判文书生成、庭审提纲生成、案件材料梳理、文书精修 |
| 检察官 / 检察官助理 | 审查逮捕、审查起诉、不起诉、刑事抗诉、刑事赔偿 | 起诉书/不起诉决定书生成、审查报告撰写 |
| 司法局工作人员 | 行政复议 | 行政复议决定书生成、复议材料梳理 |

> 业务系统通过顶部切换按钮（法院 / 检察院 / 司法局）切换，切换后案由树、案字、文书类型/模板、需求模板、示例案件随之联动。该切换为原型演示用，实际一套环境只存在一种业务场景。

## 2.3 产品定位

用户侧是办案人员的**核心办案辅助工作台**，覆盖以下能力闭环：

- **案件管理**：案件列表、新建/编辑/删除、文件上传、解析状态查看、生成文书入口、批量生成
- **材料组织**：案件文件页按分类管理材料、文件问答、材料树操作
- **文书生成**：列表页 token 自动判断模式 + 详情页用户选 tab 两种入口；材料生成 / 分步生成两种模式
- **文书流转**：文书详情查看、下载打印、文书精修、历史文书管理
- **个人配置**：我的要件、我的模板、我的提示词，与系统/管理后台数据合并展示

## 2.4 设计原则

1. **对用户友好，隐藏技术复杂性**：workflow、token、模型上下文限制等技术概念对用户不可见。用户只感知"材料生成 / 分步生成"两个选项与步骤序列；token 超限以"已选材料预估超出当前模型上下文限制"等业务语言提示。
2. **表单化优先于对话式**：核心办案功能（生成文书、批量生成、案件维护）采用传统 GUI + 按钮实现，不走对话式页面；对话式（chat）仅用于文书精修等需要多轮交互的场景。
3. **数据分层并存**：系统内置（case-data.js const）→ 管理后台自定义（localStorage.admin*）→ 用户侧自定义（localStorage.my*），用户侧仅管理自己的数据，文书生成时三类合并展示，用户自定义项加"我的"标识。
4. **业务抽象统一**：一套代码通过配置化适配法院/检察院/司法局，差异通过 partiesLabels、caseWordListByOrg、causeTreeDataByOrg、stepConfigsByOrg 等配置映射。
5. **离线可用、零构建**：纯静态 HTML/CSS/JS，双击 `index.html` 即可运行，数据持久化于 localStorage。

# 三、整体架构

## 3.1 页面结构

本文档覆盖的 6 个用户侧核心办案页面：

```
pages/
├── cases.html              # 案件管理（主入口）
├── case-files.html         # 案件文件（材料组织 + 文书生成）
├── document-detail.html    # 文书详情（文书查看/下载/打印）
├── my-elements.html        # 我的要件（按案由维护）
├── my-templates.html       # 我的模板（个人文书模板）
└── my-prompts.html         # 我的提示词（个人生成需求说明提示词）
```

对应脚本：

| 页面 | 脚本 | 说明 |
| :--- | :--- | :--- |
| cases.html | `js/cases.js` | 案件列表、生成弹框、批量生成、新建/编辑/删除、解析弹窗、历史文书、文书精修、全部文书面板 |
| case-files.html | `js/case-files.js` | 三栏布局、材料树、材料生成/分步生成、引入案由要件、文书精修跳转、历史文书 |
| document-detail.html | `js/document-detail.js` | 左材料树 + 右文书展示、下载/打印 |
| my-elements.html | 页面内联脚本 | 案由树 + 我的要件 CRUD（无独立 JS 文件） |
| my-templates.html | `js/my-templates.js` | 个人模板 CRUD、关联文书类型与案由 |
| my-prompts.html | `js/my-prompts.js` | 个人提示词 CRUD、按文书类型分组 |

> 公共数据与工具函数集中在 `js/case-data.js`（业务系统数据、文书类型/模板、要件、workflow、模型、token 估算）与 `js/common.js`。

## 3.2 统一布局

用户侧采用**左侧导航（64px 图标栏）+ 顶部栏（64px）+ 内容区**统一布局：

```
┌─────────────────────────────────────────┐
│  侧边栏 │        顶部栏（页面标题）        │
│  64px   ├────────────────────────────────┤
│         │                                │
│  💬 聊天 │         内容区                 │
│  ✅ 任务 │         （自适应）              │
│  📁 案件 │                                │
│  📝 文书 │                                │
│  📚 知识 │                                │
└─────────┴────────────────────────────────┘
```

案件文件页（case-files.html）、文书详情页（document-detail.html）、我的要件/模板/提示词页采用独立全屏布局（新标签页打开），不挂左侧导航，顶部提供返回链接。

## 3.3 导航与入口

- **主入口**：案件管理页（`cases.html`）为用户侧主入口，登录后默认跳转。
- **顶部快捷入口**：案件列表页头部 `.header-actions` 集中放置「我的要件」「我的模板」「我的提示词」「全部文书」四个按钮（与个人配置相关入口集中放置）。
  - 我的要件：`openMyElements()` → 新标签页打开 `my-elements.html`
  - 我的模板：`openMyTemplates()` → 新标签页打开 `my-templates.html?org=当前业务系统`
  - 我的提示词：`openMyPrompts()` → 新标签页打开 `my-prompts.html?org=当前业务系统`
- **案件详情入口**：案件列表点击案件名称 → 新标签页打开 `case-files.html?caseId=xxx`。
- **文书详情入口**：历史文书/全部文书面板点击"查看" → `document-detail.html?caseId=xxx&docId=xxx`。
- **我的要件上下文入口**：案件详情页"引入案由要件"弹框内"管理我的要件"链接 → `my-elements.html?cause=当前案由`，页面自动选中对应案由。

# 四、各模块详述

## 4.1 案件管理（cases.html）

### 4.1.1 功能概述

案件管理是用户侧主入口，承载案件列表、案件全生命周期操作（新建/编辑/删除/补充上传）、生成文书入口（单案/批量）、解析状态查看、历史文书/全部文书管理、文书精修、业务系统切换等核心能力。

### 4.1.2 页面结构

```
[案件管理页]
├─ 顶部操作栏
│   ├─ 业务系统切换按钮组（法院/检察院/司法局）+ 浮框提示
│   ├─ 页面标题（如"法院审判业务"）
│   └─ 操作按钮：同步案件（预留）｜ 新建案件 ｜ 列配置（齿轮）｜ 全部文书 ｜ 我的要件 ｜ 我的模板 ｜ 我的提示词
├─ 统计卡片（按业务系统动态配置标签/数字/图标）
├─ 筛选区
│   ├─ 默认：搜索框 + 案由类型
│   └─ 高级筛选（可展开）：案字 ｜ 承办人 ｜ 上传日期范围（含 7天/30天 快捷）
├─ 案件列表表头（首列全选复选框 + 案件名称 + 更新时间 + 文件数量 + 可配置列 + 操作[180px]）
├─ 案件列表行
│   ├─ 复选框
│   ├─ 案件名称（点击新标签页打开案件文件页）
│   ├─ 更新时间
│   ├─ 文件数量（点击打开 OCR 解析弹窗；解析异常时显示"正常数/总数"+"解析异常"badge）
│   ├─ 可配置列（案号/案由/当事人/承办人/上传日期/案字）
│   └─ 操作栏：文件上传 ｜ 生成文书 ｜ 更多（历史文书/编辑/删除）
├─ 浮动批量操作栏（勾选后顶部浮现）：已选 N 件 ｜ 批量生成 ｜ 删除/批量删除
└─ 列配置面板（齿轮触发，右上角悬浮）
```

### 4.1.3 核心交互流程

#### 列配置

- 默认仅展示 3 列：案件名称、更新时间、文件数量。
- 齿轮按钮打开列配置面板，可勾选添加：案号、案由、当事人、承办人、上传日期、案字。
- 案字列以标签样式（`.case-word-tag`）展示，案字按业务系统分别配置（`caseWordListByOrg`）。
- 配置自动持久化到 `localStorage.caseListColumns`，重新渲染列表与列布局（grid-template-columns 动态计算）。
- 当事人列标签随业务系统变化（原告/被告 → 犯罪嫌疑人/被害人 → 申请人/被申请人）。

#### 业务系统切换

- 点击切换按钮 → `switchBusinessSystem(type)`：更新 `localStorage.currentBusiness`、清空已选、更新页面标题、刷新案由类型/案字/承办人筛选选项、重新渲染表头与列表、关闭已打开的生成弹框/批量面板。
- 案由类型筛选下拉随业务系统动态生成（`causeFilterOptionsByOrg`），司法局为行政复议业务。

#### 生成文书弹框（token 自动判断模式 — 核心设计原则）

**触发**：案件列表行操作栏「生成文书」按钮 → `openGenModal(caseId)`。

**弹框内容**：
- 当前模型选择器（标签右侧带提示图标，悬停提示"该配置功能为管理后台功能，用户不可见，方便演示展示"）
- 案件材料上下文预估提示（根据当前模型自动计算）
  - 未超限："当前案件全部材料预估约 X tokens，未超过 Y 模型安全上限 Z tokens，将默认使用全部材料生成。"
  - 超限："当前案件全部材料预估约 X tokens，超过 Y 模型安全上限 Z tokens，请进入案件详情页选择核心材料生成文书；如勾选的核心材料仍超限，再使用分步生成。"
- 若案由存在可用要件，显示蓝色提示条"检测到该案由存在 X 个可用要件（标准 X / 我的 X），开始生成后将自动引入全部要件辅助生成。"
- 未超限时额外显示：文书类型（必选）、文书模板（非必填，展示内置模板与「我的模板」，我的模板名称后追加「（我的）」标识）、生成需求说明（非必填，含内置/我的提示词标签）

**生成判断与跳转**（列表页由 token 自动决定模式，用户无需选择）：

1. 用户选模型后，系统实时计算 `getAllMaterialsTokens(case)` 与 `getSafeContextLimit(model)`。
2. **未超限**：底部按钮为【开始生成】。点击后校验文书类型非空，跳转 `case-files.html?caseId=...&model=...&docType=...&template=...&requirement=...&source=list&autoGen=1&autoIntroduceElements=1`。案件详情页自动应用配置、默认全选材料、自动引入全部标准要件+我的要件（系统预生成答案）后直接生成。
3. **超限**：弹框隐藏文书类型/模板/需求说明，底部按钮变为【前往案件详情页配置】。点击跳转 `case-files.html?caseId=...`（效果同点击案件名称进入），由用户在详情页选核心材料并选 tab 生成。

#### 批量生成（全屏面板，橙色主题）

**触发**：勾选 ≥1 案件 → 浮动栏「批量生成」→ `openBatchFullscreen()`。

**三阶段流程**：
- **配置**：已选案件清单（可移除）+ 解析预检（存在解析异常案件显示预警，提供"跳过异常案件/仅用已识别材料生成"策略选择，默认跳过）+ 文书类型/模板/需求说明 + 生成模式说明（系统按单案全部材料 token 自动选择，超限自动跳过并记录失败原因）。
- **执行**：串行处理每个案件，逐个按全部材料 token 自动判断：未超限用材料生成；超限自动跳过标记失败（不弹窗、不中断），失败原因记录"案件材料超过当前模型上下文限制，请进入案件详情页使用分步生成"。
- **完成**：统计卡片（案件总数/成功数/总字数/总耗时）+ 操作（一键打包下载/重试失败的/新建批量任务/返回）+ 结果明细。失败项额外提供【去处理】按钮，新标签页打开 `case-files.html?caseId=...`。

#### 案件删除（三选项）

**触发**：单案"更多→删除"或批量删除 → `openCaseDeleteModal(ids)`。

**删除范围确认弹窗**（三选项，默认选"删除案件及全部材料"）：
- 删除案件及全部材料（不可恢复）：从 cases 数组移除案件。
- 仅清空原始材料，保留案件记录及已生成文书：清空 `files`，`fileCount=0`。
- 仅删除案件记录，保留原始材料及已生成文书：标记 `isDeleted` 并从列表移除（保留 files/documents）。

二次确认弹窗高亮显示案件名称与涉及材料数量，批量删除列出"已选 N 个案件"。

> ⚠️ **与交互说明的矛盾点**：《交互说明》第十八章描述为两选项（仅删材料保留文书 / 删案件全删），实际 `cases.js` 实现为三选项（多了"仅删除案件记录，保留材料与文书"）。本文档以实际实现为准。

#### 其他交互

- **新建案件**：弹框，案件名称唯一必填；上传案件包（.zip/.rar/.pdf/.doc/.docx，≤100MB，支持多选）置顶，上传首文件后案件名称自动取文件名（去扩展名）；案号/案字/案由/当事人/承办人/上传日期收纳在"补充结构化信息（选填）"折叠区；案由用三级树形选择器，案字按业务系统配置。
- **补充上传**：弹框，仅支持 .pdf/.doc/.docx（≤100MB，支持多选），含目标分类下拉（默认"其他材料"，记忆上次分类），新文件按分类聚集插入。
- **OCR 解析弹窗**：点击文件数量列打开，分"已完成/未完成"两个 tab，支持单文件/一键重新解析，文件名可点击编辑（Enter 保存，Esc 取消）。
- **历史文书弹窗**：案件操作"更多→历史文书"，列出该案已生成文书，支持预览/重新生成/文书精修/下载/删除。
- **全部文书面板**：头部「全部文书」按钮，汇总当前业务系统所有案件文书，按生成时间倒序，支持搜索，每条可查看/精修/重新生成/下载/删除。
- **文书精修**：将文书内容写入 `localStorage.refineContext`，新窗口打开 `chat.html?refine=1` 多轮对话精修。
- **同步案件**：预留入口，点击仅提示"需与案件系统接口对接后方可开发"。

### 4.1.4 数据来源

| 数据 | localStorage key | 说明 |
| :--- | :--- | :--- |
| 案件数据 | `caseAssistant_businessSystems` | 按业务系统分组（court/procuratorate/justice），含 cases 数组 |
| 当前业务系统 | `currentBusiness` | court / procuratorate / justice |
| 列配置 | `caseListColumns` | 可见列数组 |
| 当前模型 | `ai_current_model` | 模型 id |
| 补充上传分类记忆 | `last_supplement_category` | 上次使用的目标分类 |

从管理后台继承：文书类型（`adminDocTypes`，回退 `defaultDocTypesByOrg`）、文书模板（`adminDocTemplates` + my 合并）、提示词（`adminPromptTemplates` + my 合并）、案由树（`causeTreeDataByOrg`）、案字（`caseWordListByOrg`）、模型列表（`AI_MODELS`）。

### 4.1.5 与其他模块的关系

- **→ 案件文件**：点击案件名称/生成文书/去处理，新标签页打开 `case-files.html`。
- **→ 文书详情**：历史文书/全部文书"查看"跳转 `document-detail.html`。
- **→ 我的要件/模板/提示词**：头部快捷入口新标签页打开。
- **← 管理后台**：消费文书类型/模板/提示词/要件/workflow 配置。

### 4.1.6 关键约束/注意事项

- 案件列表按更新时间倒序，支持横向滚动。
- 已移除案件状态筛选项。
- 文书类型为必选，文书模板与生成需求说明非必填。
- 批量生成超限案件自动跳过并记录失败原因，不再弹窗选择。
- 搜索框同时匹配案件名称、案号、案由、当事人、材料文件名、已生成文书标题。

## 4.2 案件文件（case-files.html）

### 4.2.1 功能概述

案件文件页是材料组织与文书生成的核心工作台，采用三栏布局。左栏材料树管理案件材料，中栏配置并生成文书（材料生成 / 分步生成两个 tab），右栏展示生成结果。同时支持文件问答、补充上传、文件重命名/分类/删除、历史文书查看、文书精修跳转。管理后台可通过 `?readonly=1` 以只读模式查看。

### 4.2.2 页面结构

```
[案件文件页] 三栏布局，支持分屏比例手工调节
├─ 顶部头部：返回 ｜ 案件名称 + 案号 ｜ 模型选择器 ｜ 历史文书 ｜ 上传（只读模式隐藏）
├─ 左栏（默认 25%，可拖拽 180px~50%）：材料树
│   ├─ 顶部：搜索框 ｜ 已选 n/m ｜ 全选/取消选择 ｜ 删除已选
│   └─ 按分类分组（起诉/立案材料、证据材料、庭审材料、送达材料、身份材料、文书/判决书、其他材料）
│       └─ 每分类头部：名称 + 数量 + 上传按钮；每文件行：复选框 + 图标 + 名称 + 预览/下载/更多(编辑名/设置分类/删除)
├─ 中栏（默认 75%，生成完成态折叠）：文书设置
│   ├─ 顶部 Tab：材料生成 ｜ 分步生成（常驻，用户可随时切换）
│   ├─ 已选材料提示条（未选时蓝色提示"未选择核心材料"，已选时显示"将使用已选 n 件材料作为生成上下文"+ token 占用）
│   ├─ 智能推荐卡片（已选材料超限时显示"使用分步生成"）
│   └─ 材料生成视图：文书类型（必选）｜ 文书模板（非必填）｜ 生成需求说明（含提示词标签）｜ 【生成文书】
└─ 右栏（默认折叠，生成完成态展开占 75%）：生成结果
    ├─ 顶部 Tab：预览 ｜ 编辑 ｜ 【重新配置】｜ 【文书精修】
    └─ 文书内容 + 底部【保存】【下载】
```

**布局状态切换**：
- **配置态（默认）**：左 25% + 中 75%，右栏折叠。
- **生成完成态**：点击生成并完成后，中栏折叠，右栏展开占 75%，左栏保持 25%。
- **重新配置**：右栏【重新配置】→ 右栏折叠，中栏恢复 75%，回到配置态。

### 4.2.3 核心交互流程

#### 文件问答对话框

页面材料列表上方提供固定问答输入区：已选文件以标签展示（多文件折叠为"xxx 等 N 个文件"），文本域输入法律问题（Ctrl/Shift+Enter 换行，Enter 发送），"选择文件"按钮可将列表选中文件批量加入对话框，发送后模拟 AI 返回答案并清空。

#### 材料树操作

- **分类规则**：系统预定义 7 类；上传时可指定目标分类，未指定按文件名关键词自动分类；已上传文件可"设置分类"调整。
- **批量操作**：全选/取消全选（全部选中时按钮变"取消选择"）；已选 >0 时出现"删除已选"。
- **上传弹窗**：拖拽/点击上传，含"上传至分类"下拉（默认自动分类）。
- **文件行**：常驻预览/下载，"更多"收起编辑名称（Enter 保存，Esc 取消）/设置分类/删除（二次确认，仅删该材料，不联动删文书）。

#### 生成文书两种模式（详情页用户选 tab — 核心设计原则）

> 与列表页"token 自动判断"不同，案件详情页**用户可随时手动切换**「材料生成」「分步生成」两个 tab，两种视图配置（文书类型/模板/需求说明）共用同一套状态，切换时保持同步。

**材料生成视图**：
- 选择已勾选材料作为上下文，配置文书类型/模板/需求说明后【生成文书】。
- 【生成文书】按钮在"未选材料"或"未选文书类型"时置灰禁用。
- 已选材料超限时，表单全部置灰不可操作，显示智能推荐卡片提示"使用分步生成"。
- 生成前若案由存在要件，执行"引入案由要件"流程（见下）。

**分步生成视图**：
- 顶部常驻 Tab 激活，固定展示生成配置栏（文书类型/模板/需求说明，与材料生成视图同步）。
- 步骤列表按"业务系统 × 文书类型"自动确定（如法院裁判文书 6 步、检察院审查起诉 5 步、司法局行政复议 6 步）。
- **材料表关系**：核心材料表（左栏勾选）与分步每步材料表相互独立。进入分步视图时系统**不**预先分配核心材料到各步骤，每步初始均为未选择，由用户通过材料选择器弹窗逐一手动挑选。
- 每步 body 内展示"关联材料"区域（已选标签 + 选择材料按钮 + 材料选择建议提示）。
- 点击"选择材料"打开弹窗：搜索框 + 材料列表（全选/取消全选）+ 实时 token 校验（超限时底部红字提示并置灰确定按钮）+ 已选 n/共 m 计数。
- 勾选确定后系统**自动为该步生成 AI 内容**（无需等待底部【开始生成】），生成完成后展示已选材料摘要 + 编号列表内容 + 编辑/重新生成按钮。
- 单步生成仅基于该步已勾选材料；某步预估 token 超限时提示减少材料。
- 底部【开始生成】（生成剩余未完成步骤）/【确认并编译文书】（全部完成后出现，合并所有步骤为完整文书展示在右栏）。
- 一次仅展开一个步骤，避免纵向长滚动。

#### 分步生成的步骤序列来源（workflow 对用户不可见 — 核心设计原则）

> **workflow 是系统内部配置，对用户完全不可见**。用户只看到"材料生成/分步生成"两个 tab 与带出的步骤序列，不感知 workflow 概念。

- 步骤序列由 `getStepsConfigForDocTypeWithFallback(docTypeKey, caseWord)` 决定：
  1. 优先调用 `case-data.js` 的 `getStepsConfigForDocType(docType, caseWord)`，读 `localStorage.adminWorkflows`，按案件**案字**匹配 workflow（如"民初"匹配一审民事判决 workflow、"民终"匹配二审）。
  2. 案字从案件 `caseNumber` 正则提取（匹配 `caseWordListByOrg[org]`）。
  3. 未匹配到 workflow 时回退到内置 `stepConfigsByOrg`。
- 用户感知：仅看到步骤标题序列（如"案件信息→原告诉请→被告抗辩→争议焦点→事实认定→裁判结果"），不看到 workflow 名称、案字匹配逻辑、isBuiltin 等概念。
- workflow 不绑定生成策略：列表页由 token 自动决定模式；详情页用户选 tab；只有走"分步生成"时才根据案字匹配 workflow 取步骤序列。

#### 引入案由要件流程

材料生成/分步生成点击最终生成前执行：
1. 检查案由是否存在标准要件或"我的要件"（`getAllElementPresets(cause, org)`，合并 standard + mine）。
2. 若存在，先弹"生成文书"前置选择弹框：显示可用要件总数及分类统计，说明引入作用，黄色时间提示；底部【引入案由要件】（次按钮）/【直接生成】（主按钮）。
3. 选"引入案由要件"→ 进入"引入案由要件"弹框：默认勾选全部要件（标准/我的），可手动取消；底部【取消】/【引入要件并生成】。
4. 点击后进入答案确认页：系统 AI 预生成参考答案，用户可修改；"管理我的要件"链接跳转 `my-elements.html?cause=当前案由`。
5. 【确认并生成】将问题及答案作为上下文传入，最终文书保持原有形态。
6. 案由无要件则不弹窗，直接生成。
7. **列表页入口**（`source=list&autoGen=1&autoIntroduceElements=1`）：自动全选材料、自动引入全部要件（系统预生成答案），仅显示友好提示"已自动引入 X 个案由要件辅助生成"，不再弹选择/答案确认弹框。
8. **详情页入口**：仍执行上述前置选择弹框流程，由用户决定是否引入。

#### 文书精修

右栏【文书精修】→ 将当前文书内容写入 `localStorage.refineContext`，新窗口打开 `chat.html?refine=1` 多轮对话精修。

#### 历史文书

顶部【历史文书】→ 右侧滑出面板，列出该案已生成文书，支持查看（跳 document-detail）/精修/重新生成（跳 case-files?regenerateDocId=）/下载/删除。

#### 只读模式（管理后台查看）

`?readonly=1` 进入：body 加 readonly-mode class，头部插入"只读模式"徽章，隐藏全选/删除/上传/生成/精修/保存按钮，禁用模型/文书类型/模板/需求说明控件，仅保留预览/下载。

### 4.2.4 数据来源

| 数据 | 来源 | 说明 |
| :--- | :--- | :--- |
| 案件 + 材料 + 文书 | `caseAssistant_businessSystems` | 通过 `findCaseById(caseId)` 跨业务系统查找 |
| 材料分类 | `MATERIAL_CATEGORIES`（case-data.js） | 关键词自动分类 |
| 文书类型/模板 | `getCurrentDocTypes` / `getDocTypeTemplates` / `getFilteredDocTypeTemplates` | 合并 system+admin+my，按 cause 过滤 |
| 提示词 | `getReqTemplates(org, docType)` | 合并 admin+my，my 标 source='mine' |
| 案由要件 | `getAllElementPresets(cause, org)` | 合并 standard（admin/内置）+ mine |
| 分步步骤序列 | `getStepsConfigForDocType(docType, caseWord)` → `stepConfigsByOrg` | workflow 按案字匹配，对用户不可见 |
| 模型 + token | `AI_MODELS` / `getSafeContextLimit` / `estimateFileTokens` | 上下文占用估算 |

### 4.2.5 与其他模块的关系

- **← 案件管理**：从列表页点击案件名称/生成文书/重新生成/去处理进入。
- **→ 文书详情**：历史文书"查看"跳转。
- **→ 我的要件**：引入案由要件弹框"管理我的要件"链接跳转（携带 cause）。
- **→ AI聊天**：文书精修跳转 `chat.html?refine=1`。
- **← 管理后台**：只读模式查看。

### 4.2.6 关键约束/注意事项

- 列表页未超限跳转本页时默认全选材料并自动生成；超限跳转本页由用户手动配置。
- 已选材料 token 超限时材料生成表单锁定，强制引导分步生成。
- 分步每步材料独立维护，进入分步视图不预分配核心材料。
- 材料树宽度可拖拽调节（最小 180px，最大 50%）。
- 文件删除仅删该材料，不联动删除已生成文书。

## 4.3 文书详情（document-detail.html）

### 4.3.1 功能概述

文书详情页是已生成文书的独立展示页，左侧 1/4 展示案件材料树（高亮该文书生成时使用的已选材料），右侧 3/4 展示文书完整内容，支持返回案件列表、下载/打印文书。列表页"生成文书"未超限时已统一跳转 `case-files.html`，本页主要服务于历史文书/全部文书的"查看"入口。

### 4.3.2 页面结构

```
[文书详情页] 全屏布局
├─ 顶部导航栏：返回 ｜ 案件名称 + 文书信息（文书类型·模板）｜ 案号·生成时间 ｜ 【下载】【打印】
├─ 左侧（25%）：案件材料树
│   ├─ 顶部：材料数量（已选/总数）
│   └─ 按分类分组展示，复选框置灰禁用，高亮该文书生成时使用的已选材料
└─ 右侧（75%）：文书内容（A4 纸张样式预览）
```

### 4.3.3 核心交互流程

1. 通过 URL 参数 `caseId` + `docId`（或 model/docType/template/requirement）进入。
2. `findCaseById(caseId)` 跨业务系统查找案件；若带 docId 则从 `caseItem.documents` 取历史文书，否则按 URL 参数即时生成文书内容。
3. 渲染头部：案件名称、文书标题（文书类型·模板）、案号·生成时间。
4. 渲染左侧材料树：按 `MATERIAL_CATEGORIES` 分类，复选框 disabled，根据 `pageDoc.selectedMaterialIds` 高亮已选材料，顶部显示"已选/总数"。
5. 渲染右侧文书：历史文书取 `versions[0].content`；无 docId 时按业务系统模板即时生成（法院/检察院/司法局三套模板，含案号、当事人、案由、需求说明、签名落款）。
6. 下载：将文书内容包装为 HTML 文件下载（`.html`）。
7. 打印：`window.print()`。
8. 返回：跳转 `cases.html`。

### 4.3.4 数据来源

| 数据 | 来源 | 说明 |
| :--- | :--- | :--- |
| 案件 + 文书 | `caseAssistant_businessSystems` | `findCaseById` + `caseItem.documents` |
| 文书内容 | `pageDoc.versions[0].content` | 历史文书；无 docId 时即时生成 |
| 材料树 | `caseItem.files` + `MATERIAL_CATEGORIES` | 复选框 disabled |
| 文书类型/模板名 | `getCurrentDocTypes` / `getDocTypeTemplates` | 头部展示 |

### 4.3.5 与其他模块的关系

- **← 案件管理**：全部文书面板"查看"跳转。
- **← 案件文件**：历史文书"查看"跳转。
- **→ 案件管理**：返回按钮。

### 4.3.6 关键约束/注意事项

- 列表页"生成文书"未超限时不再跳转本页，统一跳 `case-files.html`（本页保留但不再作为生成入口）。
- 左侧材料树复选框为只读 disabled 状态，仅展示该文书生成时使用的材料范围。
- 文书内容按业务系统三套模板生成（法院判决书/检察院起诉书/司法局调解协议）。

## 4.4 我的要件（my-elements.html）

### 4.4.1 功能概述

我的要件页供用户按案由维护个人自定义要件。生成文书时，"我的要件"与标准要件（管理后台/内置）合并作为可选上下文引入，帮助文书更精确。入口位于案件列表页顶部（与"我的模板""我的提示词"并列），案件详情页"引入案由要件"弹框内另设"管理我的要件"链接（携带 `cause` 参数定位案由）。

### 4.4.2 页面结构

```
[我的要件页] 独立全屏布局
├─ 顶部：返回链接 + 页面标题"我的要件" + 业务系统切换按钮组（法院/检察院/司法局）
├─ 左侧（260px）：案由树（3 级，与新增案件案由选择器一致，来自 causeTreeDataByOrg）
│   ├─ 顶部搜索框：实时过滤叶子案由，匹配项父级自动展开
│   ├─ 置顶分组：hover 叶子案由显示图钉按钮，置顶项集中在树顶部（localStorage.myPinnedCauses）
│   └─ level-1 大类 → level-2 中类 → 叶子案由（后缀显示我的要件数量）
└─ 右侧：该案由下的"我的要件"列表
    ├─ 顶部"新增我的要件"按钮
    ├─ 每项：名称 + 说明 + 问题 + 编辑/删除
    └─ 新增/编辑表单（列表底部内联展开）：名称 + 说明 + 问题
```

### 4.4.3 核心交互流程

1. 从 URL 读取 `cause` 参数，自动选中对应案由并展开其所在大类/中类，展示其我的要件。
2. 业务系统切换后左侧案由树刷新。
3. 左侧搜索框实时过滤叶子案由；hover 叶子案由显示图钉可置顶。
4. 点击案由 → 右侧展示该案由的我的要件列表。
5. 新增/编辑：列表底部内联展开表单，填写名称、说明、问题后保存。
6. 删除：二次确认后移除。
7. 右侧**仅展示"我的要件"**，不展示"标准要件"（标准要件在引入案由要件弹窗中只读展示）。

### 4.4.4 数据来源

| 数据 | localStorage key | 说明 |
| :--- | :--- | :--- |
| 我的要件 | `myElementPresets`（按业务系统×案由分组） | 结构同 adminElementPresets |
| 置顶案由 | `myPinnedCauses` | 按业务系统分组 |
| 案由树 | `causeTreeDataByOrg`（case-data.js const） | 三级结构 |

从管理后台继承：标准要件（`adminElementPresets`，回退 `elementPresetsByCause`）。`getAllElementPresets(cause, org)` 合并 standard + mine 返回。

### 4.4.5 与其他模块的关系

- **← 案件管理**：头部"我的要件"快捷入口（无 cause 参数）。
- **← 案件文件**：引入案由要件弹框"管理我的要件"链接（携带 cause 参数定位案由）。
- **→ 文书生成**：生成时 `getAllElementPresets` 合并 standard + mine 引入，分别加"标准""我的"标识。

### 4.4.6 关键约束/注意事项

- 仅管理自己的要件，不显示系统内置与管理后台标准要件。
- 每个要件仅包含一个问题。
- 引入要件后系统预生成参考答案，用户可修改。
- 从详情页/弹窗进入时 URL 携带 cause 自动定位案由。

## 4.5 我的模板（my-templates.html）

### 4.5.1 功能概述

我的模板页供用户维护个人文书模板，关联文书类型与案由。文书生成时与系统内置/管理后台模板合并展示，用户自定义项名称后追加"（我的）"标识。入口位于案件列表页顶部。

### 4.5.2 页面结构

```
[我的模板页] 独立全屏布局
├─ 顶部：返回链接 + 页面标题"维护个人文书模板，关联文书类型与案由" + 业务系统切换按钮组
├─ 左侧（220px）：文书类型列表
│   ├─ 全部（默认选中，显示总数）
│   └─ 当前业务系统的文书类型项（每项显示该类型下我的模板数量）
└─ 右侧：我的模板列表
    ├─ 顶部"新增"按钮
    ├─ 每项：模板名 + "我的"徽章 + 所属类型 + 关联案由（chip 标签，空=通用）+ 编辑/删除
    └─ 新增/编辑表单（内联展开）：模板名（必填）+ 所属文书类型（必填）+ 关联案由（3级树多选，空=通用）+ 模板正文（可选）
```

### 4.5.3 核心交互流程

1. 从 URL 读取 `org` 参数自动定位业务系统。
2. 业务系统切换后左侧文书类型列表与右侧模板列表刷新。
3. 左侧点击文书类型筛选右侧列表。
4. 新增/编辑：内联展开表单（同时只允许一个编辑态）。
   - 模板名（必填）、所属文书类型（必填，从 `getAdminDocTypes(org)` 取）。
   - 关联案由：3 级案由树勾选（`causeTreeDataByOrg`），不选=通用；勾选时父节点显示"已选/总数"徽章。
   - 模板正文（可选 textarea，留空由 AI 自动生成）。
5. 保存：校验必填字段，生成唯一 key（`t` + 时间戳 base36），写入 `localStorage.myDocTemplates`。
6. 删除：二次确认后移除，不影响系统内置与管理后台数据。

### 4.5.4 数据来源

| 数据 | localStorage key | 说明 |
| :--- | :--- | :--- |
| 我的模板 | `myDocTemplates`（按业务系统分组） | key→{name, docType, causes[], content} |
| 文书类型 | `getAdminDocTypes(org)` | 回退 `defaultDocTypesByOrg` |
| 案由树 | `causeTreeDataByOrg` | 3 级勾选 |

### 4.5.5 与其他模块的关系

- **← 案件管理**：头部"我的模板"快捷入口（携带 org 参数）。
- **→ 文书生成**：`case-data.js` 的 `mergeMyDocTemplates(org, system)` 在 `mergeAdminDocTemplates` 之后调用，用户自定义模板 key 加 `my-` 前缀合并到 `system.docTemplates`；`cases.js`/`case-files.js` 模板下拉渲染时名称后追加"（我的）"；`getFilteredDocTypeTemplates` 按 cause 过滤时自动包含用户自定义项。

### 4.5.6 关键约束/注意事项

- 仅管理自己的模板，不显示系统内置与管理后台自定义项。
- 用户自定义模板 key 合并时加 `my-` 前缀，避免与管理后台 key 冲突。
- 关联案由为空表示通用模板（所有案由可用）。
- 合并优先级（高→低）：用户侧自定义（`my-` 前缀 / "（我的）"标识）> 管理后台自定义（覆盖同名内置）> 系统内置默认值。
- 无"恢复默认"功能（管理后台提示词才有）。

# 五、通用交互规范

## 5.1 生成文书流程（token 自动判断 vs 用户选 tab — 核心设计原则）

| 入口 | 模式决定方式 | 用户感知 |
| :--- | :--- | :--- |
| **案件列表页「生成文书」弹框** | 系统按当前模型 token 自动判断 | 未超限→【开始生成】默认全选材料并跳详情页自动生成；超限→【前往案件详情页配置】由用户手动配置 |
| **案件列表页「批量生成」** | 系统按单案全部材料 token 自动判断 | 未超限→材料生成；超限→自动跳过标记失败，提供【去处理】跳详情页 |
| **案件详情页** | **用户手动选 tab** | 用户可随时在「材料生成」「分步生成」间切换；已选材料超限时智能推荐卡片提示使用分步生成 |

> 这是核心设计原则：列表页对用户屏蔽"材料生成/分步生成"选择，由系统自动判断；详情页才暴露两个 tab 让用户自主选择。

## 5.2 workflow 对用户的不可见性（核心设计原则）

- **workflow 是系统内部配置，对用户完全不可见**。workflow 的本质是"分步生成模式下使用哪一套步骤序列"的配置容器，按"业务系统 × 文书类型"分组，由管理后台维护（`localStorage.adminWorkflows`）。
- 用户感知层面：只看到"材料生成/分步生成"两个 tab 与带出的步骤序列（如"案件信息→原告诉请→被告抗辩→争议焦点→事实认定→裁判结果"），不感知 workflow 名称、案字匹配逻辑、isBuiltin、步骤 id 等概念。
- 系统匹配逻辑（对用户不可见）：从案件 `caseNumber` 提取案字（如"民初/民终/刑初"）→ 按"业务系统×文书类型×案字"匹配 workflow → 取其步骤序列；未匹配到回退内置 `stepConfigsByOrg`。
- workflow 不绑定生成策略：列表页由 token 自动决定模式；详情页用户选 tab；只有走"分步生成"时才根据案字匹配 workflow 取步骤序列。

## 5.3 模态框/通知/加载状态

- **模态框关闭规则**：点击关闭按钮 / 点击遮罩层 / 按 ESC / 点击取消按钮，四种方式统一支持（部分弹窗如批量生成执行中点返回需二次确认）。
- **通知**：`showNotification(msg, type)`，type 支持 success/warning/error/info，自动消失。
- **加载状态**：生成文书时显示 spinner + "AI正在生成文书..."；分步生成当前步骤显示骨架屏；批量生成显示队列状态（pending/current/done/failed）+ 已用时计时器。
- **二次确认**：删除案件/材料/文书/模板/提示词/要件均需二次确认，确认文案高亮关键信息（案件名称、材料数量）。

## 5.4 表单验证

- **必填校验**：案件名称（新建/编辑）、文书类型（生成文书）、模板名+所属文书类型（我的模板）、所属文书类型+标签名+正文（我的提示词）、要件名+问题（我的要件/管理后台要件）。
- **失焦校验**：必填字段失焦时校验非空，错误时聚焦回该字段并提示。
- **文件校验**：新建案件包 .zip/.rar/.pdf/.doc/.docx（≤100MB）；补充上传仅 .pdf/.doc/.docx（≤100MB）。
- **token 校验**：材料选择器弹窗实时统计已选材料预估 token，超限时红字提示并置灰确定按钮；分步每步生成前校验该步 token。
- **唯一性校验**：同一 docType 下 workflow 案字不可重复（管理后台）；步骤 id 同 workflow 内唯一。

# 六、技术约束

1. **纯静态文件交付**：仅 HTML/CSS/JS/图片/字体，浏览器直接解析，不依赖 npm/webpack/vite/tsc 等构建工具。
2. **零外部依赖（离线铁律）**：严禁 CDN 链接引用外部资源；第三方库须下载至 `libs/` 目录相对路径引用，图片字体放 `assets/`。
   > ⚠️ **现状提示**：`cases.html`/`case-files.html`/`document-detail.html`/`my-elements.html` 当前仍引用 Google Fonts 与 Font Awesome CDN（`fonts.googleapis.com`、`cdnjs.cloudflare.com`），违反离线铁律；`my-templates.html`/`my-prompts.html` 已改用本地 `../libs/font-awesome-all.min.css`。后续迭代应统一迁移至 `libs/` 本地副本。
3. **轻量数据存储**：仅 localStorage / sessionStorage / JS 内存变量；严禁数据库或后端服务。核心数据 key：`caseAssistant_businessSystems`（案件）、`currentBusiness`、`ai_current_model`、`caseListColumns`、`myDocTemplates`、`myPromptTemplates`、`myElementPresets`、`myPinnedCauses`、`last_supplement_category`、`refineContext`。
4. **无服务器依赖**：严禁 fetch('localhost')、SSE 等依赖 HTTP 服务器的逻辑；页面间通信用 localStorage 或 URL 参数（如 `caseId`/`docId`/`org`/`cause`/`source`/`autoGen`/`autoIntroduceElements`/`regenerateDocId`/`readonly`）。
5. **数据分层并存**：系统内置（case-data.js const）→ 管理后台自定义（`admin*`）→ 用户侧自定义（`my*`），用户侧仅管理自己数据，生成时合并展示，合并优先级：用户侧 > 管理后台 > 系统内置。
